# Интерфейс на TypeScript без цепочки поставок: схема защиты

Дата отчёта: 2026-11-18. Все источники прочитаны 2026-11-18; у каждого указана дата события или публикации.
Пометки: **[пров.]** — сверено с документацией или первичным текстом; **[втор.]** — только пересказ в статьях; **[не пров.]** — из памяти или предложение, не проверялось.

Подмена имени и «галлюцинированные» имена (slopsquatting): ИИ придумывает правдоподобное имя пакета, злоумышленник его занимает; задокументирован `react-codeshift`, массовой кампании на 2026-05 нет [втор.]. Подмена внутреннего имени публичным (dependency confusion) за два года конкретным случаем не подтверждена: механизм остаётся, дата не названа [не пров.].

**Выводы.**
1. Большая часть вреда — запуск чужого кода на машине разработчика или сборки, где лежат секреты. Закрывается запретом скриптов, сборкой без секретов и без сети.
2. Скрипты — не всё: AsyncAPI и chalk сработали при запуске, Miasma — через `binding.gyp`. Против них нужны срок выдержки, ревью и ограничение того, что код интерфейса может сделать в готовом продукте.
3. Подпись происхождения (provenance) не доказывает безопасность: у TanStack, Red Hat, AsyncAPI она была настоящей. Мы её не считаем проверкой.
4. Вредные версии жили 1,5–5 часов (arrayref 86–107 мин, chalk ~2,5 ч, Nx 4–5 ч, AsyncAPI ~1,3 ч). Выдержка версии в 7 суток отсекает всё это с запасом; от долгоживущей закладки и от вредного с первого дня пакета она не спасает.

## 2. Схема по слоям

**Слой 1. Выбор зависимостей** (стоимость: иногда пишем 100 строк сами).
- Список разрешённых (`docs/ts/DEPS.md`, по образцу `docs/porting/DEPS.md`): имя, версия, зачем, чем нельзя заменить. Нет строки — нет пакета.
- Потолок (предложение, число уточнить на первом прототипе): ≤ 12 прямых и ≤ 150 пакетов в блокировке, считая инструменты сборки.
- Критерии: не заменяется платформой или 100 своими строками; нет `install`-скриптов и `binding.gyp`; нет зависимостей из git и по URL; нет скачивания бинарников; ≥ 1 год на реестре; ≥ 2 публикующих или организация; открытый репозиторий; лицензия из набора `DEPS.md`. Число загрузок не критерий: axios и chalk были самыми скачиваемыми.

**Слой 2. Получение** (стоимость: обновления идут пачкой раз в месяц).
- Блокировка с хешами целостности, `install --frozen-lockfile`; один реестр в `.npmrc`; своих пакетов в реестре нет (только `workspace:`), поэтому подмене внутреннего имени нечему подменяться.
- Скрипты выключены, список исключений пуст по умолчанию. Выдержка версии ≥ 7 суток. Зависимости из git и по URL запрещены.
- Получение — отдельный шаг с сетью и без секретов; результат (хранилище пакетов) архивируется с хешем. Сборка берёт только его и идёт без сети. [не пров.: `pnpm fetch` и `--offline` — из памяти; у Yarn документирован `enableNetwork: false`, `enableOfflineMode` [пров.]]

Сравнение менеджеров по текущей документации:

| | Скрипты зависимостей | Выдержка версии | git/URL-зависимости | Целостность и офлайн |
|---|---|---|---|---|
| npm 12 (GA 2026-07-08) | выключены (`allowScripts`), пропуск с предупреждением; `strict-allow-scripts` — ошибка [втор., Socket] | `min-release-age` есть (npm ≥ 11.10 по Microsoft), по умолчанию не включена [втор.] | `--allow-git=none`, `--allow-remote=none` по умолчанию [втор.] | `npm ci` |
| pnpm | `strictDepBuilds` вкл.; разрешения в `allowBuilds` [пров., pnpm.io/supply-chain-security] | `minimumReleaseAge` 1440 мин по умолчанию (страница не называет версию) [пров.] | `blockExoticSubdeps` вкл. [пров.]; `trustPolicy: no-downgrade` — отказ, если доверие к пакету упало, по умолчанию не задан [пров.] | `--frozen-lockfile` [не пров.] |
| Yarn 4 | `enableScripts: false` [пров.] | `npmMinimalAgeGate: "1w"` [пров.] | `approvedGitRepositories` [пров.] | `checksumBehavior: throw`, `enableHardenedMode`, `enableNetwork`, `enableOfflineMode` [пров.] |
| Bun | `ignoreScripts: false` — **не безопасно по умолчанию** [пров., bunfig] | `minimumReleaseAge` по умолчанию выключена, в секундах [пров.] | — | `frozenLockfile: false` по умолчанию [пров.]; есть `install.security.scanner` |

Выбор: **pnpm** с явно записанными настройками (не полагаемся на умолчания версии) и проверкой, что они на месте. Запасной вариант — Yarn 4: у него больше защитных настроек по умолчанию. Окончательно выберет ведущий после часа проб. Bun — нет: умолчания небезопасны.

**Слой 3. Проверка каждого обновления** (стоимость: час ведущего на пачку).
- Сравнение содержимого пакета, а не только `package.json`: `npm diff` между версиями и с репозиторием [не пров.]. Читает ведущий; писатель не принимает свои же зависимости.
- Автоматический скрипт `scripts/ts-dep-check.sh` (написать): падает, если в блокировке новое имя, у пакета появились `scripts`, `binding.gyp`, `bin`, зависимость из git/URL, вызовы `child_process`, `eval`, `new Function`, чтение `process.env`, сетевые вызовы, файл > 200 КБ в пакете, который был маленьким. Это наша эвристика, не готовый инструмент.
- Предупреждение «версия снята/устарела» не повод обновляться: в Rust-случае снятие старых версий было приманкой.

**Слой 4. Сборка** (стоимость: отдельная машина или контейнер).
- Изолированная среда без сети и без секретов; ключ подписи в ней отсутствует. Собираем дважды, сравниваем хеш `dist/`; расхождение — отказ.
- Подписывает отдельный шаг на отдельной машине: вход — готовый `dist/` и его хеш, чужой код там не запускается.
- Если CI в GitHub: нет `pull_request_target`, действия закреплены по хешу коммита, а не по тегу (изменяемые теги — открытая дыра, Socket). Подпись происхождения от реестра нам не нужна: мы в npm ничего не публикуем. Доверенная публикация (OIDC) нужна только тем, кого мы берём, и сигналом не считается.

**Слой 5. Готовый продукт.**
- Интерфейс — статический набор файлов внутри подписанной программы. Ни `node_modules`, ни менеджера пакетов на машине клиента, ничего не скачивается при работе.
- CSP задаётся в конфигурации Tauri — иначе защиты нет [пров.]. Предложение: `default-src 'self'`; `connect-src ipc: http://ipc.localhost`; без удалённых источников, без `unsafe-eval`, без `unsafe-inline` для скриптов. В примере документации `style-src` содержит `'unsafe-inline'` — мы его не копируем. Хеши и nonce для собранных файлов Tauri добавляет сам [пров.].
- Права (capabilities): привязаны к метке окна; своих команд, зарегистрированных через `invoke_handler`, по умолчанию может вызывать **любое** окно, пока не перечислить их через `AppManifest::commands` в `build.rs` [пров.]. Правило: перечислить; плагины файлов, оболочки и сети не подключать; адресов `remote.urls` нет.
- Шаблон изоляции (Isolation): песочница-iframe проверяет каждый вызов интерфейса, ключи шифрования AES-GCM меняются при каждом запуске; рекомендован документацией против зависимостей. Требует встроенных в сборку скриптов; сам модуль изоляции — без зависимостей [пров.].
- Команды движка узкие: нет «выполни команду» и «прочитай любой путь». Опасные действия агента подтверждает **движок собственным окном**, не кнопкой в интерфейсе: захваченный интерфейс иначе нажмёт её сам.

**Слой 6. Обновления продукта.**
- Подпись обновления обязательна, отключить нельзя [пров.]. Ставится только версия выше текущей; понижение — только своим `version_comparator` [пров.]. TLS обязателен в боевом режиме [пров.].
- Ключ: в сборку передаётся переменной окружения [пров.]; у нас — только на машине подписи, офлайн, резервная копия отдельно (потеря ключа = нет обновлений у установленных).
- Откат: выпускаем исправление с большей версией; старый подписанный релиз хранится; сервер может снять версию. Смена ключа и серверный откат в документации не описаны — **придумать самим до первого клиента** [не пров.].

## 3. Что остаётся открытым

- Вредный код, который мы приняли и не заметили (долгая закладка; запутанный код). Мы не убираем риск, а ограничиваем ущерб: интерфейс не может сам читать файлы, запускать программы и ходить в сеть.
- Захваченный интерфейс всё равно может вызвать разрешённые команды движка и показать пользователю ложное окно. Защита — узкие команды и подтверждения движком; полной гарантии нет.
- Машина ведущего и машина сборки: пока на них лежат секреты, любой запуск чужого кода опасен. Правило «установку делает только изолированный шаг» держится на дисциплине.
- Выдержка 7 суток не ловит пакет, вредный с первого дня, и медленную закладку.
- Уязвимость самого системного окна (WebKitGTK, WebView2), Tauri, Rust-зависимости, кража ключа подписи, ошибка проверяющего.

## 4. Rust (crates.io)

Что есть, по файлам репозитория:
- `Cargo.lock` с контрольными суммами (в записях есть `checksum`); около 278 записей.
- `docs/porting/DEPS.md` — список разрешённых прямых зависимостей с точными версиями, датой выпуска, лицензией. **Проверены только прямые** — дерево целиком в файле объявлено «после первой сборки».
- `scripts/verify.sh` ставит `CARGO_NET_OFFLINE=true`; `rust-toolchain.toml` закрепляет 1.97.1; есть `scripts/build-landlock-run.sh` (содержимое не читал).
- Урок arrayref к нам не относится сейчас: `proc-macro2 1.0.107` в блокировке настоящий, `arrayref`, `internment`, `append-only-vec` в `Cargo.lock` не найдены (проверено `grep`).

Чего нет: `deny.toml`, `cargo-vet`, каталога `vendor/` (офлайн держится на локальном кэше Cargo — откуда он наполнен, не проверено), `--locked` в `verify.sh` (в скриптах не найдено). Запрета сборочных скриптов нет и быть не может: `build.rs` и макросы выполняются при каждой сборке — это аналог `postinstall`, который нельзя выключить. Встроенной выдержки версий в Cargo нет: предложение `global-min-publish-age` (rust-lang/cargo#17335) на 2026-08-21 не было принято, дальнейшего статуса не проверял [втор.].

Что добавить (ничего не ставил):
- `cargo-deny`: четыре проверки — `advisories`, `bans`, `licenses`, `sources` [пров., документация] — в `deny.toml`; `sources` ограничить одним реестром.
- Проверка блокировки: новое имя в `Cargo.lock`, которого нет в разрешённом списке и в выверенном дереве, — отказ (так ловится `proc-macro1`).
- `cargo vendor` + замена источника, сборка с `--locked --offline` (флаги [пров.]); проверка контрольных сумм при этом — по документации не подтверждена.
- `cargo-vet`: записи аудитов и исключения [пров.]; кто публикует общие аудиты, не подтверждено. Реально — для 10–20 самых опасных (с `build.rs`, макросов, сетевых).

## 5. Правила для репозитория (одна страница)

**Писатель.**
1. Не выполняет `install`, `add`, `update`, не правит `package.json`, блокировку, `.npmrc`, `pnpm-workspace.yaml`. Нужен пакет — вопрос ведущему с причиной и тремя строками «почему не своими силами».
2. Не называет пакет по памяти или по подсказке модели: имени нет в `docs/ts/DEPS.md` — его нет (slopsquatting).
3. Не запускает чужие скрипты, не открывает чужие проекты, не создаёт `.claude/`, `.vscode/tasks.json`.
4. Код интерфейса: без `eval`, `new Function`, динамического `import()` URL, `fetch` на внешние адреса, встроенных скриптов; доступ к системе только через именованные команды движка.
5. Новая команда движка — отдельная строка в списке команд и в `build.rs`; без неё интерфейс её не вызовет.

**Ведущий перед приёмом зависимости.**
1. Строка в `docs/ts/DEPS.md`: версия, дата выпуска (≥ 7 суток), лицензия, зачем, чем нельзя заменить, число новых пакетов в блокировке.
2. Критерии слоя 1 выполнены; потолок не превышен.
3. `scripts/ts-dep-check.sh` зелёный; сравнение содержимого версий прочитано; для нового пакета — прочитан весь код, что попадёт в сборку.
4. Настройки менеджера на месте (скрипты выкл., выдержка, git/URL выкл.); `allowBuilds`/исключения не выросли без записи.
5. Сборка дважды даёт один хеш; в `dist/` нет внешних адресов и `eval`; CSP и права не изменились.
6. Раз в месяц пачкой обновлений; срочное исправление безопасности — отдельно, с ручным чтением диффа.

## 6. Клиенту, пять предложений

Окно HoH — готовый набор файлов внутри подписанной программы: на вашем компьютере нет менеджера пакетов, и при работе ничего не скачивается. Сторонний код в окне — из короткого списка; каждую версию мы берём не раньше чем через неделю после выпуска, сверяем с предыдущей и собираем без сети и без секретов. Окно технически не может читать ваши файлы, запускать программы или обращаться в сеть — только вызывать перечисленные команды движка. Обновления принимаются только с нашей подписью, а старые версии не ставятся поверх новых. Это снижает риск, но не обнуляет: ошибку проверяющего, дыру в системном окне и кражу ключа подписи мы исключить не можем.

## Не проверено (сводно)
Выбор и поведение `pnpm fetch --offline`, `npm diff`, Yarn с кэшем в репозитории; умолчания pnpm по версиям (страница версий не называет); умолчание `min-release-age` в npm 12; `build-landlock-run.sh`; нынешний статус `global-min-publish-age`; поддержка смены ключа в обновлении Tauri; `freezePrototype` и прочие настройки окна; содержимое `.cargo/registry` у ведущего. Числа потолка (12/150) и срок 7 суток — наши предложения.
