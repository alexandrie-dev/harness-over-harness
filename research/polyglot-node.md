# HOH-27: Node для инструментов, добавляемых агентом

19.11.2026. Все внешние ссылки ниже просмотрены в эту дату. Это предложение для расширений продукта; движок пишем свой на Rust, dsh не включаем.

**Рекомендация:** поставлять закреплённый Node отдельным файлом рядом с HoH, с проверкой зависимостей и обязательной песочницей ОС. Для первой версии разрешить чистые JS-зависимости без нативных модулей. Это сохраняет полезную часть npm и соответствует позиции «не параноидально»: автоматические проверки вместо обязательного чтения каждой библиотеки.

Основа — [наши слои](supply-chain-ts.md), [окно, §5 и §7](../docs/window.md), [проверяющий скрипт](../scripts/ui-supply-check.sh) и [описание проверок](../scripts/tests/ui-supply/README.md). Для окна уже предусмотрены хеши, семь суток, запрет установочных скриптов, лицензии, audit и чистое окружение; исключение picomatch касается только сборки окна, расширения его не наследуют. Общие договоры пакетов описаны в [параллельном исследовании](polyglot-packages.md); здесь — выбор исполнителя.

## 1. Откуда берётся Node

Официальная [страница загрузки](https://nodejs.org/en/download) показывает 26.13.1 LTS; предлагаемое начальное закрепление — ровно эта версия, отдельно для каждой ОС/архитектуры. В процессе подготовки поставки берём официальный архив. Сначала проверяем подпись `SHASUMS256.txt.asc`, получаем проверенный `SHASUMS256.txt`, затем сверяем SHA-256 архива: это [официальная процедура](https://github.com/nodejs/node#verifying-binaries). Ключи выпуска закрепляем проверенными отпечатками; обновление ключей проходит наше ревью, скачанный вместе с архивом произвольный ключ не подходит.

Распакованный Node, его хеш и лицензии входят в нашу подписанную поставку; расширение не может менять этот файл. Запуск по абсолютному пути, без поиска в PATH. Политика предложения: поддерживаемая LTS, плановые исправления ежемесячно, срочные исправления безопасности отдельно; переход на новую основную ветку после проверки совместимости. [Node рекомендует LTS для продукта](https://nodejs.org/en/about/previous-releases).

Node пользователя экономит место, но его происхождение, настройки и обновления нам неизвестны. В первой версии его не используем. Оценка бюджета Linux x64: 40–100 МБ загрузки, 100–200 МБ на диске для Node с pnpm, плюс зависимости инструментов; точный размер не измерен.

## 2. Как появляются зависимости

Пользователь и агент проходят один путь. Они передают исходники и желаемые зависимости. Наш установщик переносит только разрешённые поля в отдельный каталог: чужие `.npmrc`, `pnpm-workspace.yaml`, `.pnpmfile.*`, готовые `node_modules` и настройки загрузки исполнителей не принимаются.

Берём закреплённый pnpm, как в окне, сейчас 12.21.0. Наш служебный процесс без секретов разрешает версии через единственный реестр и формирует кандидат `pnpm-lock.yaml`. Прямые версии точные, всё дерево имеет SHA-512. Наш проверяющий код сверяет даты, хеши и содержимое архивов, лицензии и известные уязвимости. Новые имена показываем явно: выдуманное агентом имя не становится разрешённым автоматически.

Настройки: `minimumReleaseAge: 10080`, `minimumReleaseAgeStrict: true`, `minimumReleaseAgeIgnoreMissingTime: false`, `trustLockfile: false`, исключения возраста пусты. Значит, нет даты или зрелой версии — отказ. См. [pnpm о возрасте и блокировке](https://pnpm.io/settings/dependency-resolution).

`ignoreScripts: true`, `allowBuilds: {}`, `strictDepBuilds: true`, `ignorePnpmfile: true`; запрет git/URL-зависимостей, `binding.gyp`, нативных модулей и автоматической загрузки Node/pnpm. Одного ignoreScripts недостаточно: [он не отключает pnpmfile](https://pnpm.io/settings/build); нужен [отдельный запрет](https://pnpm.io/pnpmfile#ignorepnpmfile). Хранилище своё, без чужого кэша результатов установочных скриптов.

Получение идёт через наш небольшой посредник с разрешённым списком всего дерева «имя—версия—хеш», единственным источником registry.npmjs.org и запретом посторонних адресов/перенаправлений. Полноценный сервер зеркала сначала не нужен. После одобрения дерева [pnpm fetch](https://pnpm.io/cli/fetch) наполняет хранилище; затем [install --offline --frozen-lockfile --ignore-scripts](https://pnpm.io/cli/install) собирает каталог без сети. Недостающий архив — ошибка. Офлайн-поставка может уже содержать проверенное хранилище.

Пишем обёртку политики, посредник получения, проверку архивов, хранилище неизменяемых версий и экран установки; свой решатель npm-зависимостей не пишем. Конфигурация принадлежит HoH. pnpm тоже часть закреплённой поставки.

Node умеет [стирать часть синтаксиса TS](https://nodejs.org/download/release/v26.13.1/docs/api/typescript.html), но не проверяет типы, игнорирует tsconfig, не поддерживает TSX и TS внутри node_modules. Поэтому обычный пакет поставляет JS; нужное преобразование TS выполняется отдельным ограниченным шагом нашим закреплённым компилятором.

## 3. Где выполняется код

Каждый инструмент — отдельный процесс. `--permission` и `--allow-fs-read` дают чтение кода и выбранных файлов; запись — только в разрешённые папки. Не выдаём разрешения на дочерние процессы, нативные модули, FFI, inspector и прямую сеть. Это дополнительный предохранитель: [Node прямо не обещает защиту от вредоносного кода](https://nodejs.org/download/release/v26.13.1/docs/api/permissions.html).

Основная граница Linux — bubblewrap/Landlock из направления песочницы bash, с отдельными процессами/PID, закрытыми сокетами и дескрипторами, чистым окружением без NODE_OPTIONS, NODE_PATH, LD_PRELOAD и секретов. Код/зависимости доступны только для чтения; время, память, процессы и размер вывода ограничены. Один Landlock не задаёт список доменов: сеть закрыта ОС, HTTP запрашивается через движок, который проверяет адрес, перенаправления и доступ к локальным сетям. При отсутствии нужных ограничений запуск запрещён. Имеющиеся landlock-run и общие типы hoh-sandbox ещё не означают готовый профиль Node: его надо написать.

При сохранении показываем права. Отдельное окно подтверждает действие; MAC связывает хеш кода, блокировку зависимостей и права. Ключ расширению недоступен. Новые права требуют нового согласия; обновление не подменяет уже одобренные байты.

## 4. Что видит пользователь

«Добавить инструмент» → «Проверяем зависимости» → «Читает: Документы/Отчёты; меняет: Результаты; сайты: example.org». Затем отдельное «Разрешить и сохранить».

Причины остановки: «Версия слишком новая, доступна с 25 ноября», «Контрольная сумма не совпала», «Нужен неподдерживаемый нативный модуль». Обновление показывает изменения и дополнительные права; старая версия работает до решения, отключение и откат доступны. Предупреждение: разрешённые данные всё ещё могут уйти на разрешённый сайт; неделя и хеш не доказывают добросовестность кода.

## 5. Сравнение

Оценки человеко-недель: Linux, один разработчик, после общего договора пакета и подтверждений; включены установка, ограничения и приёмка.

| Вариант | Получение исполнителя | Зависимости | Права | Окно | Работа, оценка |
|---|---|---|---|---|---|
| Наш Node | Проверенный официальный бинарник; обновляем мы | Схема выше | ОС + permission | Всё готовится внутри HoH | 3–5 |
| Встроенный [QuickJS](https://bellard.org/quickjs/) | Исходники закреплены в нашей сборке; меньше поставка | npm-проверки сохраняются, Node API несовместимы | Только наши функции доступа; отдельный процесс | Те же права, сообщения несовместимости | 4–7 |
| TS→JS→[Wasm](https://github.com/bytecodealliance/javy) | Закрепляем преобразователь и [Wasmtime](https://docs.wasmtime.dev/security.html) | Сборочные зависимости тоже проверяются; npm не исчезает | Разрешённые импорты и лимиты | Те же права, появляется подготовка | 6–9 |
| Внешний исполнитель пользователя | Проверяем путь/версию; происхождение неизвестно | Нужна та же контролируемая установка | Та же обязательная ОС | Просьба установить/обновить исполнитель | 2–4 |

Предпочитаю наш Node: меньше собственного слоя совместимости. QuickJS разумнее, если заранее ограничить инструменты нашим маленьким API; это другой компромисс, выбранный параллельным исследованием.

**Не проверено:** бинарники, подписи и размеры фактически; обходы песочницы; совместимость библиотек и pnpm с предложенной обёрткой; macOS/Windows; сроки на практике. Выполнено только чтение, без установок, сборок, тестов и запусков проверок.
