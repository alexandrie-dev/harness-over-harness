# HOH-27: пакеты на Markdown, Rust, Go и TypeScript

19.11.2026. Исследование чтением исходников и документации; все внешние ссылки просмотрены в эту дату. Ниже — предложение, не реализованная поддержка.

**Рекомендация:** общий договор пакета и отдельные процессы с JSON-RPC по stdio; Rust/Go поставляются готовыми программами, TypeScript — JavaScript для нашего отдельного исполнителя QuickJS. Движок остаётся Rust, план переноса сохраняется. WASM — следующий возможный исполнитель.

## Что уже есть

В [kernel](../docs/kernel.md) `PluginDef::of<P>()` описывает статически слинкованный Rust-код; `plugin_dyn` выбирает такое описание, чужие библиотеки не загружает. Установка вынесена из loader.

Прочитаны [PLAN](../PLAN.md), [границы движка](v1-engine-scope.codex.md), [окно](../docs/window.md), [цепочка поставок](supply-chain-ts.md), исходники `hoh-skill`, `hoh-tools`, `hoh-protocol`. Последний уже содержит `Permissions`, таблицу привилегированных методов и проверку MAC; поддержки пакетов там пока нет.

В dsh (`/mnt/toshiba/alexandrie/hoh/refs/deepseek-harness/packages/`) `skill/skill` объединяет поставщиков, `skill-filesystem` читает `SKILL.md` с именем/описанием, `tool-skill` загружает инструкции агенту. `boot/app-boot` разрешает установленные npm-пакеты и слои профиля. `mcp/mcp-client` превращает внешние инструменты в `ToolDefinition`; его stdio-транспорт очищает окружение, но сам запуск SDK не доказывает изоляцию HoH.

## Сравнение границ

Время и размеры ниже **оценочные**, без измерений; размер означает добавку к поставке.

| Вариант | Права и защита | Запуск, сбои | Автор и поставка |
|---|---|---|---|
| Процесс, JSON-RPC/MCP | Сам канал ничего не ограничивает. Нужны ограничения ОС и проверяемые запросы к движку на файлы, сеть, запуск программ | Оценка 2–50 мс для небольшой native-программы; падение отделено, зависший процесс можно убить | Обычные Rust/Go; двоичные файлы под ОС/архитектуру, без отдельной VM. Оценка небольшого пакета: Rust 0,5–10 МБ, Go 2–10 МБ; TS требует исполнителя |
| WASM components, Wasmtime | Доступ только через выданные импорты: папки, HTTP, отдельный запуск программ через движок. Голые сокеты не обеспечивают список доменов | Ошибка гостя становится trap; лимиты памяти/времени обязательны. Оценка 1–20 мс с кэшем, первая компиляция — десятки/сотни мс | WIT, привязки и отдельная сборочная цепочка. Оценка Wasmtime 10–40 МБ; переносимость лучше |
| Общая библиотека/FFI | Код получает права движка; независимая песочница исчезает | Быстрый вызов, но сбой может уронить движок | Несовместимость ABI, платформ и Go runtime; не рекомендую |

Изоляция WASM описана [Wasmtime](https://docs.wasmtime.dev/security.html), лицензия — [Apache-2.0 с LLVM exception](https://github.com/bytecodealliance/wasmtime). WASI 0.2 остаётся полезной целью существующих инструментов; 0.3 добавляет асинхронные вызовы. По [релизам](https://github.com/WebAssembly/WASI/releases) актуальна 0.3.2 от 13.10.2026; [roadmap](https://wasi.dev/roadmap) отстаёт, помечая её planned. Наличие стандарта не означает поддержку каждым языком.

Удаление типов не проверяет типы; конструкции вроде enum требуют преобразования. Для первого TS-пакета автор поставляет исходник и готовый JS, собранный закреплённым компилятором. Node допустим у автора при сборке, в продукт не входит. Оценка старта такого исполнителя — 2–50 мс; встроенный интерпретатор не требует JIT. Процесс QuickJS защищаем ОС: ошибка C-движка тогда не становится ошибкой основного процесса.

## Go

[Go 1.24](https://go.dev/doc/go1.24#wasm) добавил экспорт функций и reactor для wasip1. В [списке платформ Go 1.27](https://raw.githubusercontent.com/golang/go/go1.27.0/src/internal/platform/zosarch.go) есть wasip1/wasm, wasip2 отсутствует. wasip1 — модуль, не готовый компонент; потребуется адаптация. [TinyGo поддерживает обе цели](https://tinygo.org/docs/guides/webassembly/wasi/), но совместимость конкретных библиотек требует пробы. Native-процесс сохраняет обычные библиотеки Go, не требует установленного Go у клиента; поэтому он первый путь.

## Минимум заложить сейчас

1. **Ядро:** встроенный `PackageHost` как обычный Rust-плагин. Через существующие `ToolsService::register` и `SkillRegistry::register_provider` он владеет регистрациями; выгрузка fiber отменяет вызовы, снимает инструменты, завершает процессы. Менять `Plugin`, типизированные сервисы и макросы не требуется. Пакет объявляет tools, skills, `settingsSchema`; настройки хранятся под его ID. Произвольные сервисы, UI-код и подписки на внутренние события пока не экспортируем.
2. **Манифест:** `formatVersion, id, version, digest, execution:{kind,entry,target?,runtime?}, tools:[{name,description,inputSchema,outputSchema}], skills, settingsSchema, requestedPermissions`. Виды: `skill|process|javascript`; будущий `wasm` согласуется версией. Хеш охватывает весь пакет, включая исходники и готовый JS; runtime закрепляется версией. Установка читает данные, не запускает hooks.
3. **Граница исполнения:** `PackageRunner.call(tool,args,hostContext)`, cancel/dispose. Собственный JSON-RPC v1 по строкам: initialize с версией/возможностями, tools/call, cancel, shutdown; обратные `host/fs|http|process`. stdout только сообщения, stderr журнал; ограничения кадров, времени, памяти. Движок назначает `packageId,digest,sessionId,callId,grantRef`; пакет не выбирает чужую личность. Это не полная реализация MCP; протокол отделён от окно↔движок. Имена инструментов получают префикс пакета, встроенные имена не замещаются.
4. **Права:** пересечение прав пакета, сотрудника, задачи и текущего вызова. Файлы через проверку путей/ссылок, сеть через посредника с проверкой DNS, перенаправлений и разрешённых адресов; дочерние программы отдельно разрешаются. Песочница закрывает прямой обход, окружение/дескрипторы очищаются. Если защита недоступна, запуск запрещён. Запуск самого исполнителя движком не даёт пакету права запускать программы.
5. **Окно:** `hoh/package/list|get|install|enable|remove`, `package.changed`; сведения `id,version,digest,kind,status,tools,requestedPermissions,grantedPermissions,error?`, у версии задачи — ссылка на пакет. Install/enable/update/rollback с выдачей прав включить в `PRIVILEGED_METHODS`. Действие для MAC связывает хеш пакета, настройки и права; ключ остаётся у хоста. Новая версия требует пересмотра согласия.

## Автор, приёмка и порядок

Автор кладёт манифест, SKILL.md либо программу/JS и ресурсы; импортирует пакет в окне, подтверждает права, включает, вызывает инструмент агентом. Программа отвечает на initialize, обрабатывает tools/call по имени из манифеста и возвращает JSON по outputSchema; язык за этой границей не виден.

Четыре примера: `read-note({path})→{text}`. Rust/Go/TS вызывают host/fs; MD учит агента читать через штатный инструмент. Для одинакового внешнего инструмента нужен общий task-tool: MD запускает ограниченный агентный проход, проверяет выходную схему, наследует права во вложенных вызовах. MD сам функцию не исполняет; результат зависит от модели. Проверить установку, видимость, вызов, отказ вне папки/сети, отзыв прав, падение и выгрузку.

HOH-13 сохраняет черновик→пример→«да»→неизменяемую версию. Разрешение инструмента не заменяет публикацию задачи. Язык программ модели остаётся открытым; сборка черновиков требует отдельной изоляции.

**Оценка:** сейчас 2–4 человеко-дня на договоры и поля рядом с протоколом/подтверждениями window-chat; чат ими не задерживать. После рабочего чата и песочницы: 4–7 человеко-недель на Linux-версию host, изоляцию, QuickJS, установку, четыре примера и руководство. WASM — отдельно ещё 2–4 недели на пробу.

**Не проверено:** исполнение, размеры HoH, задержки, полное дерево лицензий, MPL-обязательства сборки, платформенная изоляция и совместимость библиотек. Ничего не устанавливал, не собирал и не запускал; четыре пакета пока не реализованы.
