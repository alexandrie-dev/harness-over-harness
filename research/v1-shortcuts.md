# Чем сократить 65 неначатых строк описи первой версии (18.11, ~18:00)

Сводка двух исследований: [v1-shortcuts-ab.md](v1-shortcuts-ab.md) (варианты а и б, Sonnet, сеть, клоны
`codex-rs` `662a634e` и `goose` `f6aef1c4`) и [v1-shortcuts-c.md](v1-shortcuts-c.md) (вариант в, Codex по локальному
клону dsh). Список строк — [v1-unstarted.tsv](v1-unstarted.tsv): 65 строк, 69 000 строк исходника. Всё ниже —
оценка; что не проверено, помечено в исходных файлах.

## Выводы

1. **(а) готовые crates: около 1 900 строк, 3 %.** В 65 строках всего восемь сторонних npm-библиотек
   (`chokidar`, `koffi`, `diff`, `@js-temporal/polyfill`, `p-limit`, `node-pty`, `yaml`, `turndown`), и замена для
   каждой уже выбрана в `docs/porting/DEPS.md` §5.5. Берём точечно: `zstd`, `notify`, `portable-pty`,
   `sysinfo`/`procfs`, `process-wrap`.
2. **(б) части Codex и Goose: около 200 строк, ничего существенного.** 65 строк — это контракты над ядром dsh и
   тексты для модели; у Codex и Goose этого слоя нет, типы сообщений и формат журнала другие.
   - Codex: на crates.io официальных crates нет. Отдельно отделяются только `utils/pty`, `file-search`,
     `execpolicy`, `process-hardening`. Песочница тянет 26–29 внутренних crates, `apply-patch` — 44, клиент MCP — 46.
   - Goose: опубликован как `0.1.0-alpha.14` и завязан на свои типы сообщений (33 тыс. строк). Песочницы нет.
   - Цена: перестают совпадать журнал V4, схемы инструментов и тексты. Для цикла агента и хранения сессий это
     **все 242 сценария**: доказательство эквивалентности пропадает.
   - Лицензии подходят (Apache-2.0), дело не в них.
3. **(в) оставить TypeScript отдельным процессом Node — единственный заметный рычаг.** Сценарии продолжают
   доказывать поведение продукта целиком (гибридного), но не то, что часть написана на Rust. Цена:
   - Node в поставке и отдельная сборка JS при выпуске;
   - бинарные модули (`node-pty`, `koffi`) для процессов и файлов;
   - новые проверки стыка: отмена, падение Node посреди записи, порядок событий, завершение дочерних процессов.
     Их нет, это новая работа.
   Где выгодно:
   - **Office** (`office-kit`, 1 399): узкий набор операций «перевести и отрисовать», и внешний движок всё равно
     остаётся внешним.
   - **Старые миграции журнала** (`session-format-v3-to-v4`, 1 702, плюс catalog 154): чистые функции над
     целым файлом.
   - **Процессы, оболочка и файлы** (около 9 700 + 4 700): выгодно, только если именно они задержат движок.
     Это глубокий стык: каждый вызов инструмента идёт через RPC, и Node становится обязательной частью ядра.
   - **Весь движок dsh за SDK.** Самый широкий вариант: окно и новые функции (сотрудники, задачи, расписание)
     можно делать уже сейчас против готового движка dsh, а перенос на Rust идёт параллельно и подменяет движок,
     когда догонит. Протокол окна уже совместим с SDK dsh. Цена: методы `hoh/*` пришлось бы писать сначала на
     TypeScript внутри dsh, а потом второй раз на Rust.
   Для мелких строк (30–60 строк исходника) отдельный процесс дороже переноса.
4. **(г) ручной перенос** остаётся основным путём для 65 строк.

## Новая оценка срока (оценка)

- **Только (г) с точечными crates (а):** 69 тыс. → ≈ 67 тыс. строк. Срок прежний: 3–5 суток круглосуточно
  нынешним составом. Нижняя граница 30–45 ч не меняется.
- **(г) + (в) для Office и старых миграций:** минус ≈ 4 тыс. строк (6 %) — около 2–3 ч работы. Плюс Node в
  поставке и стык с проверками — примерно столько же новой работы. Чистого выигрыша по сроку почти нет; смысл
  только в том, чтобы не переносить движок Office вообще.
- **(в) для процессов, оболочки и файлов:** минус до 14 тыс. строк (20 %), но стык проходит через каждый вызов
  инструмента. По моей оценке экономит меньше суток и добавляет постоянную зависимость ядра от Node. Не рекомендую.
- **Весь движок dsh за SDK на время:** перенос не ускоряет, но продукт (окно с сотрудниками и задачами) можно
  показывать раньше: срок определяется окном и методами `hoh/*`, а не 69 тыс. строк. Решение о направлении —
  за основателем.

## Рекомендация

Продолжать ручной перенос (г) с точечными crates (а). (б) не брать. (в) взять для Office, если основатель
согласен на Node в составе. Если важна ранняя демонстрация, вынести на решение основателя вариант «окно поверх
движка dsh на время переноса».
