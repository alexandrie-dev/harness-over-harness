## Отличия от образца

- Публичная миграция реализует синхронные трейты `hoh-session-format`: события и строки передаются по значению, заголовки заимствуются, `finish` возвращает `u64`. Каталог в тестах использует production codecs и цепочку v0→v1→v2. `restore_released_v2_artifact` принимает и возвращает принадлежащий вызывающему артефакт; исходная проверка идентичности объекта заменена равенством и проверкой сохранения расширений.
- Имена объектов-экспортов представлены константами `RELEASED_V1_SESSION_FORMAT_CODEC`, `RELEASED_V2_SESSION_FORMAT_CODEC`, `SESSION_FORMAT_V1_TO_V2`; последние две имеют новые типы `ReleasedV2SessionFormatCodec`, `SessionFormatV1ToV2` для реализации трейтов. Inventory представлен неизменяемым lookup `ReleasedV2EventDispositions` с `get`/`iter`, возвращающим owned disposition; `released_v2_event_dispositions` материализует `IndexMap` в исходном порядке. По явному пункту 5 fix-задания таблица строится один раз в private `LazyLock`: после инициализации она неизменяема; `get` клонирует только найденный disposition, `iter` — по одному элементу, materializer — всю таблицу. Тест проверяет единственное построение и независимость owned копий; счётчик построений существует только под `cfg(test)`. Константа `RELEASED_V2_EVENT_TYPES` сохраняет результат `localeCompare(..., 'en')` для замороженных ASCII-имён, без runtime-зависимости от локали; тест связывает её с отсортированными ключами таблицы.
- `src/testing/validation` доступен как `testing::validation` и через реэкспорт `testing`. Добавлена `validation::assert_released_v2_header_value`, проверяющая raw `Value` до сужения до базового `Map`; обычный header API принимает `&SessionFormatHeader`. Опциональный `relationshipHeaderVersion` представлен `Option<u64>` (`None` — версия заголовка). При переопределении версии создаётся owned копия артефакта: базовый relationship API не принимает отдельно заимствованный массив событий и другой заголовок; обычный путь ничего не копирует для этой проверки.
- Packed runs сужаются безопасно через supertrait `Any` и `into_released_assistant_chunk_run` предыдущей crate. Настоящий `ReleasedAssistantChunkRun` потребляется без раскрытия, а чужая реализация трейта идёт через свой итератор `expand`, даже при совпадающем строковом теге. Это следствие принятого Rust-контракта narrowing; никаких изменений зависимости не сделано.
- В JSON сохраняются порядок ключей, отсутствие поля и явный `null`. Удаление поля сохраняет порядок остальных, повторное добавление `sourceEventSeqs`/`surfaceOp` следует исходному порядку spread. JSON-текст и интерполяция значений используют `hoh_util_values::{js_json_parse, js_json_stringify, js_string}`; `serde_json::to_value` нужен только для преобразования структур зависимости в значения. Неизвестные поля и порядок raw chunks сохраняются общим `hoh-llm`, без собственного парсера/сборщика.
- Предусловие входа: значения должны иметь JavaScript property order, который гарантирует `js_json_parse`. `Value`, собранный вручную или через `serde_json::from_str`, итерируется в порядке вставки и не нормализуется этой crate. Исключение — порядок первого неожиданного ключа при exact-key проверке: локальный helper упорядочивает integer keys как `Object.keys`. Рекурсивные проверки используют общий предел `JS_JSON_MAX_DEPTH` (4096) и стек приложения 64 МиБ из PORTING; последовательности событий обрабатываются циклами.
- Счётчики после проверки — `u64`, время проверенных stream records — `i64`. Lookup ссылок допускает только точный целый индекс: `-1` и `2.5` не превращаются в 0 и 2. Сырые turn/step chunk-группы, время событий и время будущего seed marker хранятся как `Value` до соответствующей проверки: log time проверяет target artifact, chunk time — общий accumulator. Это сохраняет исходный порядок и тексты отказов, не добавляя раннюю проверку там, где исходник только передаёт поле или делает TS cast. Не-scalar координаты разных JSON-строк сравниваются как разные JS references, без deep equality. Прямые вызовы transformed stage с нарушением контракта уже проверенных v0 payloads могут вернуть диагностический `SessionFormatError` вместо native TypeError: такая строка не выпускается предыдущей миграцией; raw decoded assistant/chunk является исключением и проверяется отдельно, см. разбор замечаний 6–8 ниже.
- Обычные ошибки используют `hoh_session_format::SessionFormatError::Format`/`FormatWithCause`, ожидаемые отказы — `UnsupportedMigration`, ошибки assembler/accumulator — `Other` с исходной причиной. Frozen validator передаёт причину embedded-stream ошибки через существующий `SessionFormatError::new_with_cause`; она доступна через `std::error::Error::source`. Для чтения replacement из явного `null` private enum `MigrationTypeError` через `thiserror` сохраняет исходный текст native TypeError в `Other`; отсутствующие start/end дают `undefined` в сообщении отказа, явный null — `null`. Класс исходного `SessionFormatError` наследует простой `Error`, не `HarnessError`. Recoverable issue хранит текст первого отказа; JSON-операции не могут вызвать исключения getters/Proxy.
- `node:path.isAbsolute` использует предписанный общий `hoh_util_workspace_path::node_path::is_absolute`. Этот helper реализует POSIX; Linux-поведение совпадает с образцом. Для платформенного Node `path` на Windows общей зависимости пока недостаточно, см. вопросы ведущему.
- Продолжено принятое в предыдущей crate отличие plain-object inventory: `toString`, `constructor` и подобные унаследованные JS-имена здесь неизвестные event types, а не значения прототипа.

### Проверка замечаний ревью 6–8

- **6, TypeError против SessionFormatError.** Предположение о недостижимости оказалось неверным для raw decoded `assistant/chunk`: v1 codec проверяет строку/seq/ranges, но не chunk payload, а migration намеренно пропускает полный payload validator для этого типа (`migration.ts:95–105, 237–262`). Каталог действительно показывал UnsupportedMigration с причиной Format для `data:null` или `chunk:null/false`, где TS stage бросает native ошибку. Исправлено: чтение `data.turn` воспроизводит native null-property ошибку в `Other`; сырой chunk без раннего object guard передаётся общему accumulator. Тест проверяет класс/текст непосредственно у stage, а через каталог — точный текст обёртки UnsupportedMigration и сохранённую причину `Other`: TS `session-format/src/chain.ts:244–254` оборачивает native ошибку так же. Остальные `record` guards применяются к payloads, уже проверенным frozen validator либо выпущенным v0→v1; нарушение этого предусловия возможно только при самостоятельном некорректном вызове transformed stage, а не через каталог.
- **7, deep equality против `!==`.** Для валидного released turn/step это целые числа, сравнения совпадают. Но у двух повреждённых chunk-строк объектные координаты могут дойти до stage: deep equality ошибочно объединяла попытки через inherited cut и раньше возвращала UnsupportedMigration. Исправлено сравнением scalar значений и различением отдельно owned объектов/массивов; JSON строки не разделяют JS reference identity. Регрессия для обеих координат через seeded catalog проверяет поздний Format `assistant/attempt 0 … must be a non-negative safe integer`, а не прежний cut refusal.
- **8, inherited names inventory.** В замороженном списке released event types нет `toString`, `constructor`, `__proto__` и других prototype names, поэтому из released writer такие типы не выходят и не меняют успешный восстановленный артефакт. На искусственной неизвестной строке различие диагностики остаётся наблюдаемым; оно явно сохранено по указанию этого fix-задания «notes 6–8 … need no change» и ранее принятому plain-object inventory контракту v0→v1. Это не утверждение, что произвольный JSON с таким type невозможен: здесь ожидается unknown-event отказ, JS prototype lookup не эмулируется.

## Не перенесено

- Целиком не пропущена ни одна из 58 исходных групп (`codec` 11, `migration` 31, `validation` 16). Таблицы содержат 145 исходных случаев; один элемент `non-object event` не имеет представления в базовом `SessionFormatArtifact.events: Vec<Map<...>>`. Отказы для raw non-object header/row проверяются через существующие `Value` API.
- Две Proxy-проверки внутри `contains ordinary and non-SessionFormatError row failures in a recoverable tail` исключены по PORTING §8: у `Value` нет `ownKeys` и исполняемых getters. Обычные `null`/array/recoverable-prefix проверки этой группы перенесены.
- `undefined` внутри `tool/result.meta` непредставим в JSON Value; opaque guard проверен вложенным `-0.0`, который общая snapshot-функция отвергает как нелоссless JSON. Исходные проверки присутствующего/отсутствующего обычного meta перенесены.
- В non-monotonic ranges тесте нет отдельного вызова `decodeCurrentSeqRanges` из `hoh-session`: эта зависимость не разрешена manifest/заданием. Проверены тот же scalar-only wire fixture и полный round-trip через frozen v2 codec; код чужого reader не копировался.
- `Object.freeze` и JS reference identity не воспроизводятся: Rust использует владение. Самостоятельных эффектов, плагинов ядра, таймеров, локалей и конфигурации в исходнике нет.

## Вопросы ведущему

1. Закрыто: прежнее утверждение об отсутствии API причины было ошибочным. `SessionFormatError::new_with_cause` и `FormatWithCause` уже существуют в базовой crate; frozen validator теперь использует их, регрессия проверяет `Error::source().is_some()`. Зависимость не изменялась.
2. Общий `hoh_util_workspace_path::node_path` явно POSIX. Для точного Windows-поведения исходного `node:path.isAbsolute` нужен платформенный helper в общей crate; Linux завершён, Windows остаётся ограничением зависимости.
3. Закрыто изменением владельца `hoh-llm`: `AssistantStreamAccumulator::push_value` сохраняет raw `block-start`/`block-end`/`usage`/`finish` после JSON snapshot без typed field checks; порядок tool delta проверок теперь id, name, argumentsDelta. Регрессии этой crate проверяют поздний отказ malformed `finish`/`usage` через каталог. Алгоритм зависимости не копировался, зависимость этой правкой не изменялась.
4. Внешние потребители проверены до переноса с исключениями каталогов из задания: `session-format-v2-to-v3` использует dispositions/header/restore/codec, `session-format-catalog` — migration/codec, `session-persistence-jsonl` tests — также `RELEASED_V2_EVENT_TYPES`. У корневого реэкспорта `releasedV1SessionFormatCodec` не найден внешний потребитель через этот пакет (используется прямой экспорт предыдущего пакета). У `releasedV2Record`, `assertReleasedV2Keys`, `assertReleasedV2PhysicalArtifact` и `src/testing/validation` нет внешнего переносимого потребителя; они полностью перенесены в публичные модули.
