# hoh-llm-openai

Адаптер модели для локального сервера с OpenAI-совместимым Chat Completions (Qwen за vLLM, llama.cpp
server, Ollama, SGLang). Нового кода без образца в dsh: подключается в `hoh-llm` там же, где DeepSeek-адаптер
dsh (`LlmAdapter`), отдаёт `StreamChunk`.

## Что умеет

- `POST {baseUrl}/chat/completions`, `stream: true`, `stream_options.include_usage` (отключается в таблице).
  Сообщения собираются из блоков `hoh-llm`: текст, изображения (data URL, байты из `AttachmentStore`),
  вызовы и результаты инструментов. Все системные тексты сливаются в одно первое сообщение (шаблоны Qwen
  не принимают системное сообщение в середине). Блоки рассуждений в историю не возвращаются.
  Изображения из результата инструмента уходят отдельным сообщением `user` после серии `tool`.
  История проверяется до отправки: результат без вызова, вызов без результата, повтор id — `INVALID_REQUEST`.
- Инструменты — `function` с JSON Schema; `tool_choice` из конфигурации; температура, `max_tokens`, `stop` —
  из `GenerateOptions`. Ключ API необязателен.
- SSE: разбор устойчив к разрыву `data:` между кусками (в том числе внутри символа UTF-8 и между `\r` и `\n`),
  `[DONE]`, комментариям-keep-alive, объектам `error` внутри потока (и событию `event: error`),
  раннему закрытию соединения (`STREAM_CLOSED`), тишине дольше `streamIdleTimeoutMs` (`TIMEOUT`),
  отмене `AbortSignal` (`ABORTED`). Ответ обычным JSON (сервер проигнорировал `stream`) тоже переводится.
- Блоки: рассуждение, текст и каждый вызов инструмента — отдельные блоки в порядке появления.
  Вызовы собираются по `index`; имя и аргументы — склейка фрагментов (имя, повторённое целиком на каждой дельте, не удваивается). Аргументы не строкой (массив, число, boolean) — `MALFORMED_RESPONSE`; объект принимается. Нет id — придумывается уникальный;
  повтор id в одном ответе заменяется. `finish_reason`: `stop`→`stop`, `tool_calls`→`tool-calls`,
  `length`→`max-tokens`; `stop` при наличии вызовов считается `tool-calls`.
  Пустой ответ — `EMPTY_RESPONSE`.
- Рассуждения Qwen: поля `reasoning_content` и `reasoning` в дельте (vLLM, SGLang, llama.cpp, Ollama) и
  `<think>…</think>` внутри `content` (llama.cpp с `--reasoning-format none`, Ollama), в том числе тег,
  разорванный между кусками. `ReasoningFormat`: `Auto` (поля + теги с явным открытием), `ReasoningField`
  (только поля), `ThinkTags`, `ThinkTagsImplicitOpen` (в потоке только `</think>`, как у шаблонов Qwen3 thinking:
  `<think>` стоит в промпте). `Auto` неявное открытие не угадывает: одиночный `</think>` отбрасывается.
- Таблица расхождений серверов — данные в `src/compat.rs` (`ServerKind`, `Compat`): имя поля лимита токенов
  (`max_tokens`; у `ServerKind::OpenAi` — `max_completion_tokens`),
  `stream_options`, поля рассуждений, способ включить/выключить думание (`chat_template_kwargs.enable_thinking`
  или `reasoning_effort`), доверять ли id вызовов, поддержка `tool_choice: required`. Усилия модели
  (`off`/`on`, у Ollama `off`/`low`/`medium`/`high`) объявляются только там, где способ известен.
- Строгий вызов инструментов (`strictToolArguments`, по умолчанию включён): в конце ответа проверяются
  имя из объявленных, аргументы — валидный JSON-объект, наличие верхнеуровневых `required`.
  Нарушение — ошибка `MALFORMED_RESPONSE` (в таблице кодов `hoh-llm` — «можно повторить») с текстом вида
  `Tool call "weather" (id call_1) has arguments that are not valid JSON (…). Arguments received: …`.
  Пустые аргументы → `{}`. Обрезанный по `length` вызов не проверяется (его отбрасывает общий сборщик).
  При `false` аргументы идут как есть, а разбирает их конвейер инструментов.
- Лимит токенов: если сервер отвечает 400 «параметр не поддерживается» на `max_tokens` (или на
  `max_completion_tokens`), запрос один раз повторяется с другим именем поля; адаптер запоминает выбор для
  следующих запросов (правило — ниже).
- Ключ API (что и как скрывается — ровно то, что ниже, и ничего сверх):
  - `Debug` у `OpenAiConfig` и `OpenAiAdapter` пишет `[redacted]` вместо ключа.
  - Из текстов ошибок, которые адаптер возвращает (`HarnessError` и его `LlmFailure`, ошибки HTTP, SSE, списка
    моделей, `ProbeResult.error`), используемый ключ вырезается и заменяется на `[redacted]`.
  - Ключ длиной от 8 символов ищется без учёта регистра (только ASCII) и вырезается везде, где встретился.
    Ключ короче 8 символов заменяется только как целое слово, с тем же регистром (не рядом с буквой, цифрой, `_`
    и `-`): иначе однобуквенный ключ уничтожил бы любое сообщение. Поэтому короткий ключ внутри `model-abc123-x`
    не заменяется, а рядом с `/` или `=` заменяется.
  - Цепочка причин ошибки проверяется по `Display` и `Debug` каждой причины и по склеенному тексту всей цепочки
    (ключ может быть разбит между двумя причинами). Если ключ найден, причины заменяются одной ошибкой с
    очищенным текстом; без ключа ошибка возвращается как есть.
  - Модель, чей `id` содержит ключ, отбрасывается из списка моделей и из результата probe. Имя модели, переданное в
    `resolve_model` и содержащее ключ, в `LlmModelInfo` попадает очищенным.
  - Не очищается: ответ модели при успешном потоке (текст, рассуждение, аргументы вызовов). Это осознанная
    граница: ключ провайдеру отдаёт сам пользователь, а эхо ключа моделью адаптер не фильтрует и не меняет.
    Не отслеживаются закодированные виды ключа (base64, URL), разбиение ключа внутри одного поля `Debug`
    (поля печатаются раздельно), другие каналы (журналы вне адаптера, запросы, которые видит сам сервер).
- Повтор с другим именем поля лимита (`max_tokens` ↔ `max_completion_tokens`) — один раз и только если выполнено
  всё: статус ответа 400; в тексте ошибки названо именно это поле целым словом (`max_tokens_extra` и
  `not_max_tokens` не считаются); формулировка из списка (без учёта регистра):
  - имя идёт после фразы: `Unsupported parameter(s)`, `Unrecognized request argument(s) supplied`,
    `Unrecognized parameter/argument/field`, `Unknown parameter/argument/field` (после фразы может быть список
    имён через запятую или `and`);
  - имя идёт перед фразой: `is not supported`, `is unsupported`, `Extra inputs are not permitted`.
  Тело FastAPI/Pydantic `{"detail":[{"loc":["body","max_tokens"],"msg":"Extra inputs are not permitted"}]}`
  читается как `body.max_tokens: Extra inputs are not permitted` (также строка `detail`). Другие статусы
  (401, 404, 422, 429, 5xx), ошибка из тела ответа 200 (у неё нет статуса), 400 про другой параметр и 400 про
  величину значения повтора не вызывают. Другие формулировки серверов в список не входят: их надо добавлять по
  мере встречи с живыми серверами.
- `probe(base_url, model, api_key, ProbeOptions, signal)` → `{ok, latencyMs, toolCalls, models, modelListed, error}`
  для `hoh/model/probe`: `GET /models`, затем одно-токенное завершение с объявленным инструментом (при отказе
  400 — без него). Таймауты раздельные: соединение, список, завершение. Ответ 200 проверяется: нужен JSON с непустым `choices`;
  HTML, `{}` и объект `error` в теле дают `ok: false` с диагностикой (ключ вырезан). При отказе сервера на
  `max_tokens` проба повторяет запрос с `max_completion_tokens`. Не возвращает `Err`.
- `probe_first_listed(base_url, fallback_model, api_key, ProbeOptions, signal)` — то же для вызывающего без имени модели
  (пустое поле первого запуска окна): один `GET /models`, завершение идёт на первую модель списка, при недоступном или пустом
  списке — на `fallback_model`. Если список не пуст, `modelListed` всегда `true` (имени для сверки нет).

## Конфигурация (`OpenAiConfig`)

`base_url` (например `http://127.0.0.1:8080/v1`), `api_key`, `provider_name`, `server` (`Generic`/`Vllm`/
`LlamaCpp`/`Ollama`/`Sglang`/`OpenAi`), `reasoning_format`, `tool_choice`, `strict_tool_arguments`,
`model` (`context_window`, `default_max_tokens`, `image_input`), `connect_timeout_ms` (10 с),
`stream_idle_timeout_ms` (300 с: локальная модель может долго обрабатывать промпт до первого токена).
Неверная конфигурация отклоняется в `OpenAiAdapter::new`. Системный прокси не используется.

## Что не проверено

Живой проверки на реальном сервере не было. Все фикстуры в `tests/` написаны по документированным форматам
(источник — в комментарии у каждой), а не записаны с настоящих серверов. Не проверено на живых серверах:
имена полей рассуждений в конкретных версиях; `chat_template_kwargs` у llama.cpp и SGLang; `reasoning_effort`
у Ollama; повторение id вызовов у SGLang (принято по описанию, поэтому ids заменяются всегда); точный вид
`usage` в последнем фрагменте; отправка изображений (в тестах только пути без хранилища: обход `offloaded`
и отказ без `AttachmentStore`; чтение байтов через `read_image_request` не покрыто тестом); поведение
HTTPS и самоподписанных сертификатов (только http на 127.0.0.1). Схема аргументов проверяется только на
`required`, типы свойств не проверяются. Тест тайм-аута простоя использует настоящее время (200 мс).
