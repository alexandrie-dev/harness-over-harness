# hoh-window-destructive-guard — нет образца в dsh

Крейт не портирован из DeepSeek Harness: это решение для профиля окна. Профили, которые сверяются
с dsh, его не подключают.

## Зачем и чем отличается от dsh
- В dsh (и в профиле окна до этого крейта) песочница `workspace-write` пускает `rm` внутри папки
  сессии без вопроса, а классификатора опасных команд нет. Условие вехи «опасные действия
  подтверждаются» (экран `design/build-a/approval-1440.png`: «Выполнить команду в папке
  Документы/HoH: удалить 3 старых файла… Файлы не попадут в корзину») этим не выполнялось.
- Плагин `DestructiveGuard` (`WindowDestructiveGuard`) слушает `ToolsPreExecute` (waterfall) и только
  для инструмента `bash` отвечает `PreToolDecision::Ask`. Дальше работает уже существующий путь:
  `service_ask` → `hoh-user-approval` → в режиме host `approval/request` с mac. Инструменты
  `write` / `edit` / `apply_patch` внутри папки по-прежнему идут без вопроса.

## Принцип
Спрашиваем, когда нельзя исключить удаление или перезапись существующего файла. Обычные команды и
создание новых файлов — без вопроса. Что не удалось проверить (цель выбирает оболочка при запуске,
текст не разобрался, код передан другой оболочке) — тоже вопрос.

## Что спрашивается
- `rm`, `rmdir`, `unlink`, `shred`, `truncate`; `find … -delete`, `find … -exec rm …` (вложенная
  команда разбирается так же); `xargs rm`;
- `mv` / `cp`, когда итоговый путь уже существует (с учётом `-t`, `--target-directory`, папки-цели
  и масок вида `*.txt`) или проверить нельзя (`$VAR`, маска с `[...]`, цель из `xargs`);
  `-n`/`--no-clobber` — без вопроса;
- `>`, `>|`, `&>` в существующий файл (`>>`, `<`, `<<`, `>&2`, `/dev/null` — без вопроса);
  `tee` без `-a` и `dd of=` — то же правило (сверх брифа: это та же перезапись, что `>`);
- `git clean` (без `-n`), `git reset --hard`, `git checkout -- …` / `checkout .` / `-f`,
  `git switch -f`, `git restore` (кроме одного `--staged`), `git rm` (кроме `--cached`);
- непрозрачное: `eval`, `sh|bash|zsh… -c`, запуск скрипта `bash script.sh`, конвейер в оболочку
  (`| sh`), `source` / `.`, имя команды из подстановки.
- (fix0) перезапись «правкой» и распаковка: `sed -i` / `--in-place` и `perl -i` по существующим
  файлам (маска `*.txt` раскрывается; файл-цель из `find -exec` / `xargs` — вопрос, имена
  неизвестны); `rsync --delete*` и `--remove-source-files`; `tar x…` / `--extract` (без вопроса только
  `tar t…` и `tar c…` в новый архив; `tar r/u/A/--delete` и `c` в существующий архив — перезапись
  архива); `ln -f` / `-sf` поверх существующего (в том числе внутрь папки-цели, и `ln -sf target`
  из одного операнда); `install` по существующей цели; `cp`/`mv` с `-f` / `--remove-destination`
  (`-n` вместе с `-f` не отключает вопрос);
  `python|python3|node|nodejs|perl|ruby` со встроенным кодом (`-c`, `-e`, `-E`, `-p`, `--eval`,
  `-` и код из стандартного ввода: конвейер, here-document, `< файл`) — непрозрачно, как `sh -c`.
- (fix1) ещё перезапись без `>`: `curl -o` / `--output` / `-O` (имя из адреса; `--output-dir` учитывается;
  `-o -` и `/dev/null` — без вопроса), `wget -O` / `--output-document` — по существующему файлу;
  `unzip` без `-n` (без вопроса `-l -t -v -p -c -Z -z -n`, а также `-d` в папку, которой ещё нет);
  `patch` (кроме `--dry-run`, `-C`, `--check`; `-o` — по выходному файлу; файл-операнд — по нему;
  иначе имена знает только патч); `git apply` (кроме `--check`, `--stat`, `--numstat`, `--summary` и
  одного `--cached`); `awk|gawk -i inplace` (то же правило файлов, что у `sed -i`).
- `$(…)`, обратные кавычки, `<(…)` и тела here-document без кавычек у ограничителя разбираются
  рекурсивно (глубина 6); безобидное внутри (`$(date)`) вопроса не вызывает.
- Обёртки `sudo`, `env`, `command`, `nohup`, `time`, `timeout`, `nice`… снимаются; (fix2) обёртка,
  меняющая папку (`env -C DIR` / `-CDIR` / `--chdir[=]DIR`, `sudo -D DIR` / `--chdir=`), переносит
  проверку целей в новую папку **только для обёрнутой команды** (перенаправления остаются за
  оболочкой и считаются от старой; `dir` с подстановкой — папка неизвестна, цели непроверяемы);
  `env -S` / `--split-string` — непрозрачно (строка разбирается самим `env`); `cd` в той же
  строке учитывается (цель считается от новой папки; `cd` с подстановкой или в `( … )` делает
  папку неизвестной, и относительные цели считаются непроверяемыми).

## Токенизатор (`src/shell.rs`)
Свой, без новых зависимостей: кавычки, экранирование, `;`, `&`, `&&`, `||`, `|`, `|&`, группы
`( )`, перенаправления (с номером дескриптора), `$(…)`, `$((…))`, `${…}`, `$'…'`, here-document
(`<<`, `<<-`), комментарии. Слово помечается `dynamic` (часть значения даст оболочка) и `glob`.
Нечитаемое (непарная кавычка, незакрытая подстановка, перенаправление без цели) → `Unparsable` →
вопрос.

## Текст вопроса (`src/text.rs`)
- `humanText` кладётся в `display_reason` под ключом `"en"` (протокол хоста несёт один текст;
  окно показывает его как есть) — **по-русски**. Одна строка без управляющих и невидимых знаков
  (иначе `validate_human_text` отвергнет его и хост покажет английскую заглушку); имена файлов
  очищаются, список — до 4 имён и «и ещё N», имя — до 60 знаков.
- Окно выбирает пояснение по ключевым словам: «удалить» → «Файлы не попадут в корзину»,
  «перезаписать файл(ы)» → «Содержимое файла изменится». Поэтому чистая перезапись начинается с
  «Перезаписать файл …», остальное — «Выполнить команду в папке <папка>: …».
- `reason` (A-03, QA 19.11): окно показывает его в блоке «Объяснение Помощника», поэтому это русский
  текст без сырой команды: то же описание, что в заголовке, но со списком файлов до 20 (заголовок —
  до 4 и «и ещё N»), для удаления добавлено «Файлы не попадут в корзину: вернуть их будет нельзя»,
  для эскалации — «Обоснование Помощника: <justification>» (это слова модели, не команда).
  Сырая команда лежит в `Question.command` («Команда: …», до 2000 знаков), но **не уходит хосту**:
  в протоколе одобрения нет поля подробностей (только `humanText` и `reason`). Окну нужно новое
  необязательное поле, например `details` в `HostApprovalRequest`/`ApprovalView` и в
  `ApprovalRequest` (hoh-user-approval); тогда охрана кладёт туда `question.command`.

## Отступления и ограничения
- **Явная эскалация (`sandbox_permissions: "danger-full-access"`, fix1, переписано в fix4).** Охрана
  сама задаёт один русский вопрос на вызов (`escalation_prompt`, прямой `approval.request` с
  `toolName "bash"` и текстом причины `escalate sandbox to <режим>: <обоснование>`). Только если
  хост ответил `allowed-once`, охрана записывает грант `pre_approve_escalation(session, callId,
  "bash", причина)`; собственный вопрос bash об эскалации (`approve_escalation`) тратит его без
  повторного вопроса. Отклонение, отмена, таймаут, `unavailable` — гранта нет, вызов отклоняется
  охраной с тем же кодом, что и в конвейере. Грант привязан к (сессия, callId, инструмент, точная
  причина), одноразовый, живёт 5 минут; другой инструмент (например `write` с тем же callId и
  причиной того же префикса) его не получает и идёт к хосту. Саму команду в ключ не кладём: в `bash`
  причина строится из режима и обоснования вызова, а команда проверяется отдельно, до эскалации.
  Режим, равный действующему (`workspace-write`), инструмент разрешает без вопроса, поэтому он
  охрану не отключает (тест `naming_the_standing_mode_does_not_skip_the_guard`).
  Известное ограничение (принято CEO): если хост вернёт `allowed-once` на вопрос охраны, но bash
  сменит текст причины — грант не сойдётся и вопрос будет задан ещё раз (безопасный отказ).
- **Сознательно без вопроса: запуск файла-скрипта и сборки** — `python x.py`, `python -m pytest`,
  `node x.js`, `perl x.pl`, `ruby x.rb`, `make`, `npm run …`, `cargo …`, `pytest`. Любая такая программа может удалить
  или перезаписать файл, плагин этого не видит: спрашивать на каждый запуск сборки — паранойя.
  Вторая линия — песочница `workspace-write` (запись вне рабочей папки закрыта), но внутри папки она
  ничего не спрашивает. Это ограничение принято (решение CEO при приёмке fix0).
- Для оболочек (`sh`/`bash`/… `script.sh`) вопрос остаётся (шаг 2, бриф: «source неизвестного»).
- Остальное, что перезаписывает без `>`: `awk -i inplace`, `cat > f` через `dd`/`install -C`,
  `curl -o`, `wget -O`, `unzip -o`, `git apply`, `patch` — не разбирается.
- Существование цели проверяется в момент вопроса; файл, созданный раньше в той же строке
  (`touch f; echo > f`), в проверке отсутствует. Маски: только `*` и `?` в последнем компоненте.
- Рабочая папка — `WorkingDirectoryService::get(session)` (без ввода-вывода) плюс аргумент `workdir`
  инструмента bash.

## Цель с подстановкой (fix3)
Правило: слово-цель или опция со значением цели, в которых есть `$VAR`, `$(…)`, обратные кавычки,
маска, `~`, `{a,b}`, — цель непроверяема, и команда в режиме, который может перезаписать или удалить,
спрашивает. Токенизатор помечает слово `dynamic` и `lead_dynamic` (подстановка стоит в начале слова:
`$X-n` — не опция `-n`). Слово, начинающееся с `-`, но с подстановкой дальше (`-o$OUT`,
`--file=$OUT`, `-$X`), разбирается как опция: известное до подстановки читается, значение — неизвестное
(`is_operand` / `is_dynamic_option` / `take_value` / `inline_value` в `classify.rs`). Опция, которую
целиком заполняет оболочка (`-$X`, `--$X`), может оказаться любой — для команд с опасным режимом это
вопрос. Маска **без совпадений** как цель записи (`> *.x`, `--file=*.x`, `-o *.x`, `cp a *.x`) спрашивает
(цель неизвестна); как исходный операнд (`sed -i s/a/b/ *.nomatch`) — нет: оболочка передаст её
буквально, команда завершится ошибкой и ничего не перезапишет. Остаточное ограничение: слово целиком из
подстановки на месте опции (`find . $ACTION`, `cp $FLAGS a b`, `sed $F …`) неотличимо от операнда и не
считается опцией.

## Ввод-вывод (fix2)
Проверки файловой системы (`symlink_metadata`, `metadata`, чтение папки для маски) идут через трейт
`Fs` (`src/fs.rs`, настоящая реализация `RealFs`), а плагин выполняет весь разбор в
`tokio::task::spawn_blocking` (`assess_blocking`): медленный монтируемый диск или огромная папка не
держат поток рантайма. Паника в блокирующей задаче — вопрос (как нечитаемый текст). Тесты
`tests/blocking.rs`: управляемый `Fs`, блокирующийся до трёх тиков «сердцебиения» на однопоточном
рантайме (`current_thread`); при разборе на потоке рантайма тест падает.
`tar`: режим (`c/t/x/r/u/A/d/--delete`) определяется после разбора всех опций, порядок `--file=` /
`--create` / `--extract` значения не имеет (тесты `tar_mode_does_not_depend_on_the_order_of_options`).

## Тесты
- `tests/table.rs` — таблица «команда → вопрос / без вопроса» против настоящей папки (около 250
  команд: все пункты выше и обратные случаи), тексты, множественное число, безопасность одной строки.
- Сквозные: `apps/hoh/tests/window_guard.rs` (stdio собранного `hoh --profile window`, mock модели)
  и `apps/hoh/tests/window_e2e.rs`.

## `details` (sg2, A-03 продолжение; исправлено по ревью guard-a03.212333)
- `Question.command` («Команда: …») уходит хосту как `HostApprovalRequest.details` во всех трёх видах
  (удаление, перезапись, эскалация); `reason` — русское объяснение без команды.
- Обычный вопрос, как прежде, — `PreToolDecision::Ask`; в `Ask` добавлено необязательное `details`
  (`hoh-tools`, минимальная правка), его `service_ask` кладёт в `ApprovalRequest.details`. Ask завершает
  waterfall: хук после охраны не вызывается (тест `ask_details_reach_the_approval_request_and_the_ask_ends_the_waterfall`).
- Эскалация (`sandbox_permissions: "danger-full-access"`) по-прежнему идёт прямым `approval.request` с
  `details`: грант `pre_approve_escalation` должен появиться только после `allowed-once`, а ответ `Ask`
  охрана не видит (fix4). Это единственный прямой вызов.
- Обоснование модели (justification) в `reason` не попадает вовсе (fix2: фильтр «повторяет команду»
  убран — он обходился регистром, кавычками, частью пути и давал ложные срабатывания). `reason`
  эскалации целиком строит охрана и заканчивается словами «Обоснование Помощника — в подробностях».
  `details` эскалации: `Команда: <команда>\nОбоснование Помощника: <обоснование>` (команда до 2000 знаков,
  обоснование до 1500; всего не больше 3600 знаков, то есть в пределах 8192 единиц UTF-16 протокола).
  Вопрос не эскалации: `details` — только `Команда: …`. `Question.command` переименован в `Question.details`.
  Маскирование адресов в `details` делает окно (`redact_text`), как для `reason`.
