## Отличия от образца
- clamp_timeout принимает Option для hint и имени (None означает timeoutMs). Исключения представлены Result с публичным enum TimeoutError; TimeoutReason реализует Error/Display с исходным текстом, code и timeout_ms.
- Миллисекунды — f64, поскольку источник принимает дробные задержки. Таймеры отбрасывают дробь, используют минимум 1 ms; TimeoutReason сохраняет исходное значение. MAX_TIMER_DELAY_MS — u64. deadline/idle_watchdog сохраняют исходную валидацию positive/finite/max. AbortSignal::timeout не возвращает Result: Node-style неподдерживаемые nonfinite/overflow delay становятся 1 ms, отрицательные/нулевые/субмиллисекундные также дают 1 ms.
- Публичные AbortSignal (Clone, Debug, Send+Sync), AbortController (new/default, Send+Sync), AbortError (new/default, Clone/Debug), DomTimeoutError (Clone/Debug) и is_abort_error реализуют утверждённый fix2 API. Прежних AbortSignal::new/abort/Default и Any-based reason нет. Отмена без причины — AbortError "This operation was aborted"; timeout — DomTimeoutError "The operation was aborted due to timeout". is_abort_error узнаёт AbortError напрямую и в SharedError, но не через source().
- Причины — hoh_error::SharedError. Первая отмена выигрывает, reason(), throw_if_aborted(), cancelled() и forwarding сохраняют ptr_eq, в том числе через BoxError и повторный SharedError::new. any синхронно принимает уже отменённый источник и передаёт первый abort; пустой any никогда не отменяется. Уже наступивший timer, в том числе с deadline ровно в момент последующего controller.abort(), имеет приоритет перед этим abort; тесты покрывают точное равенство 10 ms и вложенные any в обоих порядках. Mutex-секции короткие, через await не удерживаются; abort/Notify/watch-wake вызываются после освобождения state guards. В idle_watchdog callback сначала фиксирует право на срабатывание под WatchdogState mutex, освобождает его и только потом вызывает abort_with; reentrant-waker тест проверяет доступность mutex.
- Дополнительный публичный builder AbortError::with_cause(impl Into<BoxError>) — единственное расширение заданного cancellation API. Он нужен hoh-atomic-write: node:timers/promises возвращает AbortError с текстом "The operation was aborted" и cause = причина сигнала. Поле cause приватное; стандартный Error::source возвращает SharedError с исходной идентичностью. Остальные сигнатуры соответствуют brief.
- timeout_of принимает Option<&SharedError> и optional code. Для сигнала: `let reason = signal.reason(); timeout_of(reason.as_ref(), code)`; для пойманного SharedError: `timeout_of(Some(&caught), code)`; для BoxError: `timeout_of(SharedError::of(error.as_ref()), code)`. Таким образом классифицируется и сигнал, и брошенная причина, не только объект signal.
- Владение timeout/from_token: фоновых задач нет. Сигнал хранит Instant deadline либо clone CancellationToken и заранее созданную стабильную причину. Мост владеет одним token.cancelled_owned() future, один раз опрошенным с безопасным std::task::Wake, ссылающимся на сигнал через Weak. Пробуждение закрепляет причину синхронно внутри token.cancel(), даже без runtime/ожидающего future; порядок отмен двух token сохраняется. Никакой задачи и child_token нет. Drop последнего signal clone уничтожает registration future и снимает его waker с долгоживущего token; накопления на token нет. aborted/reason также проверяют deadline/token синхронно. cancelled() владеет своими Sleep/Notify futures, Drop ожидания сразу освобождает таймер/подписки. Результат any держит sources сильно, а sources держат результаты только через Weak: результат переживает внешние source handles и по Drop снимает свои слабые связи. Активное ожидание само владеет signal clone, поэтому lifetime явен. Ни dropped timeout, ни dropped bridge не оставляет задачу или таймер.
- aborted(), reason() и throw_if_aborted() разрешены без Tokio runtime и не создают Sleep: Instant::now() вне runtime использует монотонные часы std; timer становится aborted при чтении после deadline, bridge — при cancel token. Проверены создание/чтение без runtime и expired timer без ожидания реального времени. Async-ожидание timer через cancelled() использует Tokio Sleep и требует runtime. Debug только копирует cached reason под одним state mutex, ничего не refresh/abort; поэтому ещё не наблюдавшийся elapsed timer может печататься как reason: None.
- Стоимость чтения: aborted() и throw_if_aborted() используют reason(). Для уже закреплённой причины это O(1): проверка state под mutex, затем отдельное чтение/clone SharedError под тем же mutex. Для pending одиночного controller/timer — O(1) state-locks и Instant::now(); bridge дополнительно читает is_cancelled() CancellationToken (его внутренняя синхронизация); token_registration mutex при чтении не берётся. Pending any рекурсивно проверяет sources и читает event каждого: время зависит от числа посещений в развёрнутом графе, стек — от глубины. Ширина даёт больше ветвей, один общий узел может посещаться повторно по разным путям; в DAG с повторными aliases стоимость может расти экспоненциально с глубиной, общей мемоизации pending-обхода нет. Первое обнаружение due timer/cancel включает также закрепление причины и обход weak followers с уведомлением; последующие чтения закреплённого результата снова O(1). Это стоимость текущего переноса, не утверждение O(V+E) для произвольного DAG.
- Deadline и IdleWatchdog остаются на tokio::time и управляемых JoinHandle. Deadline отменяет таймер на Drop; в образце таймер работает до dispose() или срабатывания — Rust-поведение сохранено по решению ведущего. Положительная задержка этих helpers требует активного Tokio runtime.
- IdleWatchdog::next принимает Future вместо AsyncIterator; Future и Output должны быть Send+'static из-за eager Tokio task. concurrent demand и таймер фиксируются при вызове, до polling результата. Завершение demand снимает таймер даже до чтения результата; dispose/Drop watchdog снимает таймер, но не завершает outstanding next. Закрытие watch-канала не считается таймаутом.
- Согласованное прежним review отличие: при собственном таймауте demand уничтожается, а не продолжает работать как проигравший Promise.race. Возвращённый next future владеет задачей; его Drop отменяет её. IdleWatchdogError::Timeout теперь содержит SharedError с TimeoutReason, State содержит TimeoutError, Task содержит Rust JoinError. Идентичность timeout error и signal.reason сохранена. Upstream abort не сокращает outstanding demand, как в образце.

## Не проверено
Платформенных веток нет. Многопоточный тест синхронно стартует 8 abort и 4 наблюдателя: выбирается ровно одна из исходных причин, каждый наблюдатель видит ту же identity; относительный победитель одновременно начатых abort не задан однопоточным JS. Мост CancellationToken не несёт исходного reason, поэтому создаёт стабильный AbortError согласно решению ведущего. Проверены вложенные any, результат без внешних source handles, порядок, waiters и освобождение слабых связей; очень глубокие/широкие DAG не нагружались, сложность описана выше. Перенос сигнала между разными часовыми доменами (например paused Tokio и отдельный std-thread) отдельно не проверялся.
