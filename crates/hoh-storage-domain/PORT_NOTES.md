## Отличия от образца

- Плагин StorageDomainPlugin/apply имеет точное имя storage-domain и обязательную зависимость Storage (storage); дополнительная структура Deps выражает её для derive Inject. StorageDomain — дополнительное имя Rust ServiceKey для storageDomain; значение — DomainFacility, тот же экземпляр смонтирован в storage.form("domain"). Config сохраняет backend (обязателен), routes ({} по умолчанию); новых настроек нет. Динамический ctx.inject списка storage.backend.<name> выражен вспомогательным дочерним плагином MountDomain с PluginOptions.inject: сначала default backend, потом уникальные route targets. Предоставление сервиса/формы — эффекты; leftovers закрываются до unmount. Имя сервиса lifecycle берётся из hoh-storage, не дублируется.
- DomainError extends Error, поэтому это собственный thiserror struct с name/code/message/detail/cause, а не HarnessError. PlainError представляет обычные Error деклараций/неизвестной таблицы/global. DomainErrorOptions и InvalidRecordDetail сохранены; пустые table/key помечают global. Ошибки backend не перекодируются. DomainFuture — дополнительное имя Result<T, SharedError>: SharedError хранит и перекидывает тот же unknown-state по тождеству, включая задания, стоявшие в очереди до отказа. Вызвавший использует SharedError::downcast_ref/ptr_eq. Превращение в BoxError для kernel не меняет внутренний класс причины.
- Promise chain — FIFO-actor по одному на домен; enqueue/close добавляют команды синхронно под одной короткой std::sync::Mutex. Каждая запись идёт backend → память → emit. Неуспех не публикует память/событие, неизвестное состояние записывается до следующего job. Close немедленно запрещает новые записи, ждёт уже поставленные, закрывает unit и только потом снимает reservation. Повторные close делят cached outcome; reads во время drain ещё разрешены, после close closed имеет приоритет над failure.
- Tokio-задачи здесь исполняют исходные Promise open/chain, а не отменяемую работу ctx.spawn: закрытие facility само владеет drain через close_all. Снятие ожидающего future не отменяет уже начатую операцию, как и Promise; idle worker держит только receiver, команды держат Arc состояния до завершения. Нет блокировки через await. Нельзя привязывать worker к fiber вызывающего consumer: исходный handle принадлежит потребителю, а его teardown при unmount — facility. Тесты проверяют отложенную durability, drain, снятие waiters, событие при закрытии и освобождение имени. Как в образце, close_all берёт снимок уже открытых domains и отдельно не ждёт open, ещё находящийся в await.
- Записи/global читаются как Arc<V>, без defensive copies; повторные обращения и stable table/global handles сохраняют идентичность. keys/entries возвращают owned snapshot-итераторы. Публичные KvTable<K,V> и DomainGlobal<G> типизированы; Domain — единый runtime, DomainImpl — его alias. Из-за отсутствия TS literal/declaration-mapping table::<K,V>(name) и global::<G>() выбирают тип явно; неверный Rust-тип даёт PlainError (состояние, которое TypeScript исключает компилятором). Имя таблицы/domain остаётся String, как в исходнике, K может быть branded типом владельца. Статических брендов этот пакет не объявляет.
- DomainTableSpec<K,V> и DomainGlobalSpec<G> стираются через From в дополнительные ErasedTableSpec/ErasedGlobalSpec для неоднородных maps. TableDefinition/GlobalDefinition — дополнительные traits с associated types: TableKeyOf<T>/TableValueOf<T> проецируют конкретный DomainTableSpec, GlobalValueOf<T>/DomainGlobalHandleOf<T> — DomainGlobalSpec, вместо TS условных типов от всего S. ValueSchema<T> хранит parser владельца. DomainSpecInput — дополнительная unchecked декларация (JSON version/compatibleVersions и строковые layout/policy) для исходных отказов defineDomain; DomainSpec содержит проверенные u64 и закрытые KvLayout/InvalidRecords. Версии соответствуют u64 backend по PORTING §4; JSON f64 приводится только точно в пределах 2^53. Исходные JS integer-версии за пределами этого представления не поддерживаются; сохранённые record schemas не получают этого ограничения автоматически.
- Объектные ключи на входе open перечисляются как Object.entries: канонические integer-like ключи сначала по возрастанию, затем остальные по вставке. Это делает пара js_json_stringify/js_json_parse общего hoh-util-values над одними ключами. После open таблица — IndexMap как исходный Map: новые numeric keys добавляются в конец. Порядок события при записи: domain, table, key, operation, value; deleted не содержит value. Размеченный enum десериализуется по operation, ручной Serialize сохраняет исходный порядок. DomainChangedPut/Deleted/Base доступны в events, как в исходном src/events.
- Обычный Emit обёрнут catch_unwind только вокруг всей рассылки: уже committed запись не отклоняется при sync throw, а последующие слушатели после throw не запускаются — именно так устроен исходный emitChanged. Новая contained-dispatch возможность kernel здесь не используется: она меняла бы это поведение. Warn дословно domain '<name>': domain/changed listener failed: Error: <message>; Rust panic соответствует sync throw обычного Error. Асинхронные возвраты из Emit исходник здесь не наблюдает.
- До реализации просмотрены реальные потребители workspace/workspace, schedule/schedule и session/session-projection-cache. Ими прямо импортируются defineDomain, domainTable, Domain, KvTable, DomainGlobal; DomainFacility используется через ctx.storageDomain/ctx.storage.domain. Прямых внешних импортов остальных публичных source имён нет: descriptorOf, DomainSpec, DomainGlobalSpec, DomainTableSpec, TableKeyOf, TableValueOf, GlobalValueOf, DomainGlobalHandleOf, DomainError/Code/Options, InvalidRecordDetail, DomainChanged. Они всё равно перенесены; Config/apply доступны загрузчику. DomainChanged также регистрирует общий typed event даже без прямого импорта типа потребителем.

## Валидация сохранённого состояния и тексты zod

Пакет не объявляет ни одной собственной фиксированной zod-схемы record: их задают владельцы DomainSpec. Поэтому ValueSchema<T>::new принимает ручной parser Fn(&Value) → Result<T, BoxError>, вызываемый в тех же местах, что schema.parse/safeParse(null) в образце. Это **не** безусловный serde_json::from_value<T>: владелец обязан перенести stripping лишних свойств обычного z.object, .strict(), optional/default/nullable, refinements и transforms своего пакета. Никакая JSON Schema конфигурации kernel не применяется к stored records. Parser вернул значение — оно становится памятью без повторной проверки/записи; writes здесь не проверяют схему (как в исходнике). Global initial служит до первого set и не материализуется; сохранённый null — sentinel, принимающий null parser отвергается define_domain.

В tests/helpers/mod.rs вручную перенесены itemSchema = z.object({label:z.string(), count:z.number().int()}) и settingsSchema = z.object({theme:z.string()}): приём plain objects, stripping дополнительных свойств, обязательные поля без coercion, оба знака safe integer, отклонение fractions/вне safe range, сбор issues в порядке полей. Непредставимые в Value undefined/NaN/cycles/prototypes не имитируются. Тесты проверяют приём/отказ и stripping, а также typed records/global с callback-трансформацией только на read.

Точка видимого текста zod — src/index.ts, ветка backup-and-skip: String(error.cause) включён в logger.error. В src/error.rs дополнительный ZodError хранит ordered issues, Display пишет message вручную через js_json_stringify_pretty(..., 2), js_error_string добавляет исходный префикс ZodError: . Каждое поле issues формирует parser владельца: для invalid_type тестовые ручные decoder-ы дают expected, code, path, message; для int-сбоев также format/bounds как в zod. В parse_record исходные текст domain '<name>': stored record '<key>' in table '<table>' does not match its schema, detail и оригинальный cause сохранены. Дополнительный backup_and_skip_logs_the_exact_zod_cause_and_keeps_good_records сверяет всю строку журнала, включая ZodError, переносы, 2-пробельный отступ и текст Invalid input: expected number, received string. Для будущих custom/refine decoder-ов текст issues переносится в их owning crate, не заменяется сообщениями serde.

## Вопросы ведущему

Блокирующих нет. hoh-storage предоставляет всё нужное: named registry, typed service, открытый mount, descriptor/KvUnit, optional backup_record и собственный StorageError. Его файлы не менялись. Уточнение API для следующих писателей: передавать ValueSchema с faithful parser, таблицы через domain_table::<Key,Value>(schema).into(), global через DomainGlobalSpec.into(), объявление — define_domain(DomainSpecInput), open — Arc<DomainSpec>, handle — table::<Key,Value>/global::<Global>(). Ошибки DomainFuture имеют SharedError; проверять исходный класс через downcast_ref и тождество ptr_eq, без повторной упаковки.
