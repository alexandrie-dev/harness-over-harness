## Отличия от образца
- `Option<Arc<ChunkedList<T>>>` представляет пустой список; Arc разделяет старые чанки и значения. При append копируется максимум 64 Arc, T не требует Clone. Поля приватны для readonly-контракта; дополнительные методы `values/previous` предоставляют чтение.
- append_chunked_list и iterate_chunked_list принимают одинаковый Option<&Arc<ChunkedList<T>>>; итератор возвращает &T в порядке вставки.
- chunked_list_schema<T>(Value) возвращает Result<Arc<_>, serde_json::Error>. DeserializeOwned типа T заменяет Zod-схему владельца (для дополнительной валидации владелец пишет Deserialize). На каждом уровне обязательно JSON object с values-массивом длины 1..64, без неизвестных полей; previous:null и массив вместо объекта отклоняются, отсутствующий previous допустим. Прямой Deserialize использует ту же валидацию после разбора JSON в Value. Порядок JSON: values, previous.
- Валидация готового Value, восстановление, обход и Drop цепочки previous написаны циклами; shared-префикс сохраняется, уникальный хвост освобождается через Arc::into_inner (включая конкурентное освобождение Arc). Ошибочные/непосещённые JSON-хвосты также освобождаются итеративно. Тест строит 200 000 значений программно, восстанавливает/валидирует checkpoint, обходит и освобождает обе цепочки; другой тест отклоняет глубокий неверный suffix.
- Параметризованные случаи it.each сохранены циклом: 4 неверных head + 4 неверных previous; добавлена проверка null.

## Не перенесено

## Не проверено
Разбор checkpoint из текста — ответственность вызывающего кода: serde_json по умолчанию отклоняет вложенность глубже 128; Deserialize сначала разбирает JSON в Value. Для программно построенного Value используется chunked_list_schema без рекурсии по previous. Serialize и Debug остаются рекурсивными, предельная глубина их вывода не проверена; глубокий checkpoint тест строит напрямую как Value, без сериализации в текст. Рекурсия внутри произвольного пользовательского T определяется владельцем T.
