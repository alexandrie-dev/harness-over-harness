## Отличия от образца
- Размеры и счётчики — u64. Стратегии ItemRetentionStrategy и TextRetentionStrategy — закрытые enum с исходными JSON-тегами и camelCase-полями. new получает уже типизированную стратегию и не возвращает ошибку; отрицательные и дробные бюджеты отклоняются на serde-границе. Их тесты перенесены через serde, так как Rust u64 не допускает эти аргументы конструктора.
- При десериализации бюджеты со значением 2^64 или больше отклоняются, хотя Number.isInteger образца принимает и такие представимые значения JavaScript Number. Полные тексты ошибок десериализации принадлежат serde, а не образцу: проверки бюджетов используют исходную формулировку внутри сообщения, но serde может добавлять контекст и формирует собственные ошибки типов/формата.
- RetentionStrategy, RetentionUnit, RetentionLimit — публичные enum для вложенных union-типов RetentionNotice. Публичные типы данных реализуют serde; порядок полей и JSON-представление сохранены.
- ItemRetainer::finish требует T: Clone и возвращает независимый снимок Vec вместо общего изменяемого массива JavaScript. Повторный finish и последующие push разрешены; внешняя мутация снимка не меняет retainer (владение Rust).
- TextRetainer::push принимает AsRef<[u8]> (включая &str, String, Vec<u8>, &[u8]); сохраняет копии байтов, а не ссылки на изменяемый Uint8Array. Prefix Vec и скользящий suffix VecDeque ограничены теми же бюджетами. BOM и повреждённые байты декодируются как TextDecoder; при реальном промежутке стороны декодируются отдельно.
- truncate_without_splitting_surrogate_pair возвращает заимствованный &str и считает len_utf16 каждого символа, не байты UTF-8. max_chars — u64: отрицательные, дробные и нечисловые maxChars не представимы в типизированном API.

Платформенных веток нет. Одиночные суррогаты в исходной строке JavaScript не представимы в Rust str. Бюджеты за пределами u64 также не представимы.

## Вопросы ведущему
- Подтвердить Rust-владение снимком ItemRetainer::finish вместо изменяемого alias массива; это естественная граница без общего изменяемого состояния.
- Источник не валидирует maxChars функции truncateWithoutSplittingSurrogatePair: отрицательное значение имеет семантику JS slice от конца. В Rust API оставлен u64 по правилу размеров; нужен ли отдельный нетипизированный адаптер для таких вызовов?
- В README push.truncated описан как согласованный с finish, но источник вычисляет push до UTF-8 trim: при пограничном частичном символе omission в finish может быть больше. Перенесено без исправления.
