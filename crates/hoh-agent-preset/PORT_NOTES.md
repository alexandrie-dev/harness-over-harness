## Отличия от образца

1. В TS `Config` — type alias к `PresetDefinition`. Rust определяет отдельный публичный `Config`, а затем
   без потерь преобразует его в `PresetDefinition`: реестр намеренно хранит `plugins` как сырой JSON ради
   отложенных выражений, но схема этого пакета, как в образце, обязана принимать только массив.
2. Экспортируемые `PACKAGE_NAME` и `register_plugin` отсутствуют как именованные экспорты TS. Это Rust-точка
   статической интеграции с `PluginRegistry`: она регистрирует плагин, каталог ресурсов и аналог
   `EntryGroup.key = true`. Carrier-маркер не вычисляет выражения внутри дочерних строк раньше их владельцев.
3. Ресурсы доступны из каталога Cargo-крейта через `PluginRegistry::resource_dir`, а не через npm export map.
   Их содержимое совпадает с образцом побайтно.

## Не перенесено

- Исходный тест реестра использует `SkillRegistry` вместе с файловым provider и сравнивает загруженное
  содержимое с `body.trim()`. Текущий тест проверяет поставляемый корень, frontmatter и тело напрямую, но не
  воспроизводит полную композицию сервисов реестра; это остаётся интеграционной проверкой bundle.
- npm package-meta gate и реальная проверка JavaScript через `node --check` относятся к JS build/package
  окружению (PORTING.md §10). Здесь проверяются manifest/export/file relations, patch parser и базовая
  целостность JS-файлов, но не вызываются исходные `packageMetaProblems` и Node parser.
- Исходный checkout-тест вычисляет корень DSH на пять родителей выше skill-файла и проверяет JS-monorepo
  markers. У Cargo-крейта HoH другая глубина и layout, поэтому это вычисление намеренно не выполняется;
  статически проверяется точная инструкция и все исходные markers в поставляемом документе.
- Примеры POSIX/Node и PowerShell не исполняются: у Rust-крейта нет контракта на установленный DSH Node
  runtime, а PowerShell/Windows не являются средой его покрейтовых offline-тестов. Проверяются опорные
  фрагменты команд: переменные окружения, ожидание процесса, раздельный stderr и возврат exit code.
- Проверка upstream `.agents/skills/agent-experience` не относится к поставляемым файлам пакета. Вместо неё
  проверяется единственность `dsh-doc` в собственном корне и единственная ссылка на поставляемый
  `references/tool-design.md`; сам upstream wrapper не копируется в крейт.

## Не проверено

- Фактическая установка шаблонов в npm-профиль и выполнение их JavaScript остаются ответственностью
  интеграционных проверок итогового приложения.
- POSIX/Node и PowerShell-команды требуют интеграционной проверки в установленной DSH-среде; покрейтовые
  тесты гарантируют только сохранность документированного текста команд.
