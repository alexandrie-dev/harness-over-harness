# Сценарий mock для QA-прогона A («окно-чат», шаги 4–6)

Файл: `crates/hoh-llm-openai-mock/scenarios/qa-window-a.json` (38 ответов, модель `window-mock`).
Запуск: `hoh-llm-openai-mock --scenario crates/hoh-llm-openai-mock/scenarios/qa-window-a.json --listen 127.0.0.1:<свободный порт> --part-delay 0=200 --part-delay 1=100 --journal <файл>`.
**Флаги `--part-delay` обязательны для шага 4**: пауза перед каждой из 34 частей ответа 0 (200 мс, поток около 7 с) и ответа 1 (100 мс, около 3,5 с), чтобы «Стоп» можно было нажать посреди потока, а части — увидеть по отдельности. Остальные ответы идут без пауз.

## Как mock подбирает ответ (важно)

- Ответ выбирается **строго по порядку**, а не по тексту сообщения: каждый потоковый запрос модели берёт
  следующий ответ из файла. Проверочные запросы без `stream:true` (кнопка «Проверить», `/v1/models`) ответ
  не расходуют. Поэтому **фразы ниже — подсказка человеку**, mock их не читает; важно только число и порядок
  сообщений.
- Одно сообщение пользователя запускает цепочку: ответ с вызовом инструмента → после выполнения (или отказа
  в подтверждении) движок присылает результат модели → следующий ответ. Цепочка заканчивается ответом с
  одним лишь текстом. Следующее сообщение пользователя начинает новую цепочку. Длины цепочек указаны ниже.
- Запускать mock заново **перед прогоном** и после любого сбоя/повтора шага: лишнее или пропущенное
  сообщение сдвигает все последующие ответы. После конца файла mock отвечает HTTP 409.
- Если шаг «Знакомство» сам обращается к модели, его запросы тоже расходуют ответы: перезапусти mock после
  знакомства (проверь по журналу `--journal`: до первого сообщения шага 4 потоковых запросов быть не должно).
- Задержка между частями задаётся только флагом запуска `--part-delay ИНДЕКС=МС` (в JSON её нет: новое поле
  в структуре ответа сломало бы чужие тесты, строящие её литералом).

## Заготовки (создать в рабочей папке до прогона)

| файл | содержимое |
|---|---|
| `notes.txt` | три строки: `alpha`, `beta`, `gamma TODO` |
| `old-1.txt`, `old-2.txt` | любой текст (для удаления) |
| `report.txt` | любой текст (будет перезаписан) |
| `config.txt` | строка `mode = draft` |
| `script.py` | одна строка: `print("привет из python")` |

Не создавать заранее: `result.txt`, `new-file.txt`, `notes-copy.txt`, папку `qa-dir`, а также
`../qa-outside.txt` (за пределами рабочей папки). Они должны появиться (или не появиться) по ходу.

## Почему именно так

- Вопрос на `>`/`cp` возникает только если файл уже существует: поэтому `new-file.txt` и `notes-copy.txt`
  новые и не заготавливаются, а `report.txt` существует.
- `rm` спрашивает всегда, независимо от наличия файлов; `sed -i` — для существующего файла.
- Относительные имена: рабочая папка — текущая папка команд. Единственный путь наружу — `../qa-outside.txt`.
- В тексте ответов нет слов «токен», «сессия», «агент» и JSON (шаг 7).
