## Отличия от образца
- **YAML.** В Rust нет документного API с комментариями (как у пакета `yaml`). Запись `refs`/`records` правит текст по диапазонам, которые даёт `saphyr-parser`: заменяет значение на месте (хвостовой комментарий строки сохраняется), добавляет запись после последней, удаляет запись вместе с блоком комментариев непосредственно над ней, ставит `refs: {}` после удаления последней записи. После правки текст разбирается заново и сравнивается с ожидаемым снимком (`verify`); иначе запись отменяется с ошибкой.
  - Образец печатает весь документ заново (`Document.toString()`), поэтому у него «нормализуется» всё форматирование; здесь нетронутые строки остаются байт в байт — это строже, а байтовые ожидания тестов совпадают.
  - Стиль заменяемого скаляра не сохраняется (образец: тоже по правилам печати `yaml`): новое значение — простой скаляр, если читается как та же строка; иначе в двойных кавычках; многострочное — `|-`/`|`/`|+`; строки с `"` без `'` — в одинарных. Перенос по 80 колонкам не делается.
  - Документ в потоковом стиле (`{a: b}`) пересобирается как блочный **только без потерь**: если в тексте есть комментарии, теги (`!tag`, `!!str`), директивы (`%YAML`, `%TAG`), явные маркеры `---`/`...`, якоря/алиасы или число, которое не печатается обратно в том же написании (например `18446744073709551615`), запись отказывается с понятной ошибкой (`nothing was written`), файл не меняется. Образец сохраняет и то и другое, здесь это сделать нечем.
  - Явный маркер конца документа `...`: запись вставляется перед ним, удаление его не трогает (как у образца).
  - `verify` после правки сравнивает не только `refs`/`records`, но и весь остальной документ (другие верхние ключи, остальные записи секции, написание чисел); расхождение — отказ записи.
  - Целые числа в payload хранятся точно (`i64`/`u64`); образец читает их как `double` и теряет значения выше 2^53.
- **Коды разбора.** Образец показывает коды `yaml` (`BLOCK_AS_IMPLICIT_KEY` и т. п.); здесь собственные: `YAML_PARSE_ERROR`, `MULTIPLE_DOCS`, `DUPLICATE_KEY`, `UNEXPECTED_TOKEN`, `BAD_ALIAS`. Текст `invalid document … line L, column C` и правило «значения из источника никогда не цитируются» сохранены (тест `never_puts_a_credential_value_in_a_diagnostic`).
- **Позиция ошибки.** Для незакрытой кавычки `yaml` указывает конец ввода, сканер `saphyr` — место открытия; позиция пересчитывается на конец текста, чтобы `line 2, column 1` из образца совпало.
- **Наблюдатель.** `chokidar` с `awaitWriteFinish` заменён на `notify` (inotify) на каталог документа плюс своё ожидание «файл тих `debounceMs`» (скользящий debounce): события фильтруются по точному пути, по готовности наблюдателя вызывается тот же `reconcile`. Параметры `stabilityThreshold = debounceMs`, `pollInterval = max(1, min(debounceMs, 10))` передаются в шов как есть (проверяются тестом нулевого debounce). Если каталога документа ещё нет, наблюдение идёт за ближайшим существующим предком; когда каталог появляется или исчезает, наблюдатель перенацеливается и сообщает `all` (как chokidar).
- **Шов для тестов.** Публично, но `#[doc(hidden)]`: `Seams { writer, watcher }` и `LocalCredentialProvider::start(ctx, config, seams)`; плагин использует `Seams::default()`. Это замена `vi.mock('chokidar')` и `vi.mock(writeFileAtomic)` образца; без неё детерминированные тесты гонки dispose/очередь и конвейера событий не написать.
- **Окружение.** Тесты не меняют окружение процесса (`vi.stubEnv` невозможен без `unsafe`): слои «process / project-env / user-env» задаются снимком `LaunchEnvironment`, который читает провайдер (`launch_environment_of(ctx)`), как и в образце.
- **Ошибки.** Все — `BoxError` с текстом образца; классов `TypeError`/`Error` нет. Текст ошибок ОС строит `hoh_error::node_fs_error_message` (формат `ENOTDIR: …, stat '…'`), поэтому проверки `ENOTDIR`/`EISDIR` остались подстроками.
- **`warn`.** `ctx.logger().warn` принимает одну строку, а образец передаёт `(message, names, path)`; аргументы склеены в одно сообщение: `credentials-local: ignoring unknown top-level keys "A", "B" in <path>; only `refs` and `records` entries resolve`.
- **Права.** Файл создаётся `0600`, каталог `0700` (`write_file_atomic` с `mode`/`dir_mode`); проверка «читаем не только владельцем» (`mode & 0o077`) — при загрузке, при каждой перезагрузке и перед каждой записью, как в образце; на не-Unix проверка пропускается (как на Windows у образца).
- **Значения `version` и `kind` не печатаются** (отступление от образца ради безопасности: опечатка в этих полях может содержать вставленный секрет). Сообщения: `declares an unsupported version; this build reads version 1` и `has an unknown kind (expected "api-key" or "grant")`. Тесты `never_puts_an_unknown_version_or_kind_value_in_a_diagnostic` и `never_puts_an_unknown_version_in_a_reload_warning`.
- **`Debug` документа** (`CredentialsDocument`) ручной: имена записей и виды, без значений (образец: `String(document)` даёт `[object Object]`).
- **Каталог.** Существующий каталог документа с доступом для группы/остальных (`mode & 0o077`) при записи **отвергается** с указанием `chmod 700`, а не переправляется молча: путь может вести в общий каталог, который провайдер менять не вправе. Новые каталоги создаются 0700 (как у образца). Отказ — только при записи; чтение и загрузка каталог не проверяют.
- **Секреты.** `Debug` провайдера печатает только путь документа; ключи в сообщения об ошибках не попадают (проверка маски, предупреждений и диагностики разбора в тестах).
- **Очередь.** Цепочка промисов образца заменена `tokio::sync::Mutex` (FIFO): записи и перезагрузки идут по одной в порядке постановки; отказ одной не ломает очередь.
- **`describe_record`/`list_records`** не оборачиваются в очередь (как у образца: чтение снимка).

## Известные границы (не правятся)
- Секрет в имени ключа: сообщения об ошибках называют ключи (`credential ref \"…\" must match`, `unknown field`, `env \"…\"`); если вставленный секрет попал в имя ключа, оно попадёт и в текст ошибки. Образец ведёт себя так же; значения (`version`, `kind`, значения записей) не печатаются.
- Временный файл записи (`write_file_atomic`) создаётся с правами 0600, но при аварийном завершении процесса может остаться рядом с документом; чистка таких файлов не делается.
- Проверка «без потерь» для документа в потоковом стиле — консервативная и текстовая: пара ` #` или токен `!` внутри кавычек тоже даёт отказ (безопасная сторона).

## Не перенесено
- Случай `refuses a payload this document could not read back` из `records.spec.ts` (значения payload `Date`, `bigint`, функция, `NaN`): `serde_json::Value` их не представляет, поэтому отказывать нечему. Проверки `is cyclic` и `non-finite number` остаются для документа на диске (случаи «проверка документа»).
- Случай `ERR_INVALID_ARG_VALUE` для пути с NUL: у `std` нет такого кода, путь с NUL просто не открывается; отдельного теста нет.
- npm-артефакты (`package.json`, `tsconfig.json`) не переносятся.

## Не проверено
- Только Linux (inotify); macOS (FSEvents) и Windows не запускались.
- Реальное наблюдение (`notify`) покрыто одним тестом горячей перезагрузки; остальные — через шов.
- Поведение кросс-процессной блокировки проверено двумя провайдерами в одном процессе, не двумя процессами.
