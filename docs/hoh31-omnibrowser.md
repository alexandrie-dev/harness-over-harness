# HOH-31: OmniBrowser как браузер помощника — справка, 20.11

**Только справка.** Основатель решил в 15:21: для разработки и QA остаётся headless Chrome. В план и пилот OmniBrowser не входит, писателям не выдаётся. Исследование вёл исполнитель только на чтение; кроме `lightpanda help`, ничего не запускалось. Полный ответ: `/mnt/toshiba/alexandrie/hoh/research-out/hoh31-omnibrowser.md`.

**Как подключать.**
- Лучший путь — родной MCP OmniBrowser по stdio, отдельный процесс на каждую живую сессию HoH, поверх нашего `hoh-mcp-client`. Клиент уже умеет stdio и HTTP, инструкции сервера и изображения.
- `hoh-browser-use` только резервирует имя поставщика (`lib.rs:23`).
- CDP дороже: своего CDP-клиента у нас нет.
- Пакеты dsh playwright-mcp, chrome-devtools-mcp и stagehand-native не нужны. От `browser-use-runtime` нужен маленький Rust-аналог: владение сессией, очередь вызовов, очистка.

**MCP-инструменты.** Их 28: goto, search, markdown, html, screenshot, links, evaluate, extract, tree, click, fill, scroll, waitFor*, press, selectOption, setChecked, getCookies и другие (`src/browser/tools.zig:240`). Ещё есть `save`, он пишет файл: его скрыть или пропустить через нашу политику записи. Команды `session_*` работают только по HTTP.

**Чего нет в MCP.**
- Пиксельного снимка: снимок — текстовая раскладка без картинок, шрифтов и цветов.
- Кликов по координатам, загрузок, записи cookies и постоянного профиля. Всё это есть только через CDP.
- Нескольких вкладок: CDP держит один target.
- Выбор файла (file chooser) — не проверено.
