# Plugin Creator

Автор и внешний агент используют один CLI для создания и проверки Rust-плагинов HoH.
Для каждого плагина откройте отдельный worktree, чтобы его Cargo workspace и индекс
оставались независимыми от других авторов.

```sh
git worktree add -b plugin/hello ../hoh-hello HEAD
cd ../hoh-hello
cargo run --offline -p hoh -- plugin templates --json
```

Нужны закреплённый в `rust-toolchain.toml` Rust, офлайн-кеш Cargo и Python 3.11 или новее.
Если `hoh` ещё не доступен в PATH, используйте префикс
`cargo run --offline -p hoh -- plugin` для команд ниже.

```sh
hoh plugin new hello --template tool --json
hoh plugin test hello --json
```

`new` выводит каталог, два основных файла в `editFiles` и следующую команду в
`testCommand`. Шаблон `tool` регистрирует `hello_echo` и включает проверки вызова,
неверного ввода и выгрузки. Шаблон `basic` проверяет загрузку. Для события сессии
и панели выполните `hoh plugin guide session-panel` и откройте `plugins/turn-note`.

- `hoh plugin check hello --json` проверяет идентификатор, JSON-манифест и имя
  пакета в Cargo. `linkedManifest` сравнивает метаданные со встроенной копией.
- `hoh plugin test hello --json` сначала делает ту же проверку, затем запускает
  офлайн-тесты выбранного пакета. При ошибке сборки показывает до трёх
  диагностик. Полный вывод Cargo и тестов доступен по пути `log`.
- Отчёты создания, проверки и тестирования имеют `formatVersion: 1`.
  Успех помечается `ok: true`. При ошибке код выхода ненулевой, а в `issues`
  есть стабильный `code`, сообщение и, где применимо, файл, строка и подсказка.

## Подключение к движку

Для предварительного просмотра индекса выполните
`python3 scripts/generate-plugin-index.py --candidate hello --dry-run --json`.
Для локального запуска с окном используйте `scripts/plugin-dev.sh hello` в
worktree автора с настроенными `CARGO_HOME` и `CARGO_TARGET_DIR`. Скрипт
пересобирает движок с выпущенными плагинами и выбранным кандидатом, затем
печатает путь к бинарнику для уже собранного окна.

После ревью Rust-кода внесите ID в `plugins/index.json` и выполните
`python3 scripts/generate-plugin-index.py` для сборки поставки. Rust-плагин
работает внутри процесса HoH, поэтому его исходники ревьюятся как код ядра.

## Внешние плагины

В Linux-версии HoH откройте **Plugins → Install from folder** и выберите
готовую папку с `hoh-package.json`. HoH проверит пакет и сохранит его
в активном профиле. Страница Workspace откроется сразу после установки.
Для обычной страницы используйте **Open** рядом с названием.

Чтобы вывести готовый пакет в **Plugins** с кнопкой **Install**, передайте
HoH абсолютный путь к его папке в переменной `HOH_PLUGIN_PACKAGE`.

### Локальная страница для HoH

Папка пакета называется так же, как его `id`, например `hello-page`. В ней
нужны `hoh-package.json` и готовый модуль `dist/ui.js`. Если пишете на
TypeScript, соберите модуль у себя перед тем, как передавать пакет пользователю.
Свежую сборку модуля можно открыть после обновления списка в **Plugins**.

```js
export function mount(root) {
  const button = document.createElement('button');
  let clicks = 0;
  button.textContent = 'Click me';
  button.addEventListener('click', () => {
    button.textContent = `Clicks: ${++clicks}`;
  });
  root.append(button);
}
```

```json
{
  "formatVersion": 2,
  "id": "hello-page",
  "version": "1.0.0",
  "digest": "sha256:<hash of dist/ui.js>",
  "ui": { "entry": "dist/ui.js" },
  "requestedPermissions": { "ui": ["page"] },
  "contributes": {
    "ui": { "pages": [{ "id": "main", "name": "Hello page", "handler": "mount" }] }
  },
  "requires": { "services": { "ui": { "protocolVersions": [1] } } }
}
```

Подставьте SHA-256 модуля из `sha256sum dist/ui.js` и обновляйте его после
изменений. В локальном формате эта сумма связывает запись каталога с
исполняемыми байтами. Для проверки издателя потребуется подписанная поставка.

Страница открывается в отдельном окне HoH со своей webview. Модуль может
создавать элементы и обрабатывать события внутри страницы. Доступ к DOM HoH,
чатам, файлам и сети отсутствует. Состояние страницы сбрасывается при закрытии.

### Полноразмерная страница в Workspace

В Linux-версии HoH UI SDK v1 поддерживает размещение страницы в центральной
области окна. Добавьте `"sidebarLabel": "Hello Workspace"` в
`contributes.ui.pages[0]` рядом с `"handler": "mount"`. HoH использует эту
строку для пункта в **Workspace** и заголовка страницы. Обычные страницы v1
без `sidebarLabel` открываются в отдельном окне.

Используйте разрешение `page`, версию протокола `[1]` и синхронную
функцию `export function mount(root)`. HoH предоставляет изолированную WebView
и контейнер с атрибутом `data-hoh-placement="workspace"`. Плагин управляет
вёрсткой, inline-стилями, адаптацией к размеру области и своей навигацией.
Страница может хранить состояние в памяти до закрытия HoH или загрузки
другой страницы либо новой версии пакета.

В **Plugins → Install from folder** выберите папку
[hello-workspace](examples/hello-workspace/). HoH сразу откроет
**Hello Workspace** и добавит страницу в боковую панель.
Счётчик в примере позволяет проверить, что страница интерактивна и её
состояние сохраняется при переходе в чат и обратно.

### Секретарь на странице Workspace

На Linux UI SDK v4 предоставляет `sdk.secretary.propose()` для полноразмерной
страницы Workspace. Для него нужна настроенная модель HoH. Объявите разрешения
`page` и `secretary`, версию протокола `[4]` и `sidebarLabel`.

```json
{
  "formatVersion": 2,
  "id": "my-workspace",
  "version": "1.0.0",
  "digest": "sha256:<hash of dist/ui.js>",
  "ui": { "entry": "dist/ui.js" },
  "requestedPermissions": { "ui": ["page", "secretary"] },
  "contributes": {
    "ui": {
      "pages": [{ "id": "main", "name": "My workspace", "handler": "mount", "sidebarLabel": "My workspace" }]
    }
  },
  "requires": { "services": { "ui": { "protocolVersions": [4] } } }
}
```

Вызывайте `sdk.secretary.propose({ message, instructions, context })` из
`export function mount(root, sdk)` по нажатию кнопки или клавиши Enter.
Передайте текст пользователя, инструкции для модели и нужные данные страницы
в JSON-объекте `context`. Запрос поддерживает до 4 КиБ для `message`, до 12 КиБ
для `instructions` и до 128 КиБ на всё сообщение в UTF-8. HoH обрабатывает один
запрос за раз.

Метод возвращает `Promise<string>` с предложением модели. Обработайте ошибки
через `catch` и проверяйте формат ответа перед применением изменений. У модели
есть переданные плагином данные. Изменения состояния выполняет сам плагин.
HoH проверяет контрольную сумму модуля и связывает запись каталога с манифестом,
включая объявленные в нём разрешения.

### Чат секретаря на странице Workspace

На Linux UI SDK v5 поддерживает обычный чат HoH, связанный со страницей кабинета.
В манифесте страницы с `sidebarLabel` укажите версию протокола `[5]` и
`requestedPermissions.ui: ["page", "secretaryChat"]`.
HoH проверяет контрольную сумму модуля и связывает разрешение с манифестом пакета.

Из `mount(root, sdk)` привяжите к кнопкам два вызова.

- `sdk.secretary.openChat({ revision, instructions, context })` открывает
  связанный с пакетом чат HoH с обычным выбором харнесса. Сообщение отправляет
  пользователь. `revision` обозначает снимок, а JSON-объект `context`
  содержит данные кабинета. Весь запрос ограничен 128 КиБ в UTF-8.
- `sdk.secretary.getProposal()` возвращает текст предложения из связанного
  чата или `null`. HoH извлекает JSON `{ revision, reply, changes }` из блока
  `cabinet-changes` в последнем завершённом ответе. Проверяйте идентификатор
  снимка и формат, покажите предложенные правки и применяйте их только после
  подтверждения.

Оба метода возвращают `Promise` и требуют действия пользователя в активной
странице. У изолированной страницы есть доступ только к этому мосту,
а харнесс и разрешения разговора выбираются в самом HoH.

### Панель плагина рядом с чатом

UI SDK v2 на Linux позволяет добавить кнопку в **Workspace** и открыть свою
панель справа от чата. Используйте тот же формат пакета и SHA-256 модуля.
Укажите вклад `chatPanel` вместо `pages` и версию протокола `[2]`.

```json
{
  "formatVersion": 2,
  "id": "my-chat-panel",
  "version": "1.0.0",
  "digest": "sha256:<hash of dist/ui.js>",
  "ui": { "entry": "dist/ui.js" },
  "requestedPermissions": { "ui": ["sidebar", "chatPanel", "reviewQueue", "openChat"] },
  "contributes": { "ui": { "chatPanel": { "title": "My panel", "sidebarLabel": "My panel" } } },
  "requires": { "services": { "ui": { "protocolVersions": [2] } } }
}
```

Точка входа `export function mount(root, sdk)` получает DOM-контейнер панели
и объект SDK. Вёрстку, стили и взаимодействие задаёт сам плагин.

| Метод | Поведение |
| --- | --- |
| `sdk.reviewQueue.get()` | Последний снимок очереди текущего профиля. Сразу после запуска массив может быть пустым. |
| `sdk.reviewQueue.subscribe(listener)` | Вызывает `listener(items)` при подписке и при обновлении очереди. Возвращает функцию отписки. |
| `sdk.openChat(threadId)` | Открывает чат из текущей очереди. Вызывайте синхронно из пользовательского нажатия. |

Запись содержит `threadId`, `title`, `project` (название), `state`
(`question`, `approval` или `review`) и `startedAt` (миллисекунды Unix).
В очередь попадают до 512 чатов, сначала самые ранние. Файлы, пути проектов,
текст вопросов, история, сеть и команды движка недоступны панели.
Панель работает в изолированной WebView и допускает собственные inline-стили.
После установки откройте панель по её кнопке в **Workspace**.

## Сессия автора в окне HoH

Откройте **Plugin Creator**, добавьте или выберите обычную папку будущего плагина
и выберите Claude или Codex. Подойдёт пустой каталог. Git и исходники HoH не
требуются. Мастер запускает чат в выбранной папке и передаёт встроенную
инструкцию по самостоятельной разработке плагина. Для интерактивного
интерфейса мастер использует формат локальной страницы или панели, описанный выше.
Для Markdown-навыка можно подготовить черновик манифеста и `SKILL.md`
без сборки. Подкоманды CLI для Rust-компонентов внутри исходников описаны выше.

### Вопросы перед работой

Каждый новый чат Plugin Creator начинается с обсуждения. Харнесс сначала сверяется с комплектом документации и проверяет, поддерживает ли
SDK нужный сценарий. Затем задаёт по одному вопросу за раз и предлагает свой
вариант с обоснованием. Если API не хватает, обозначает пробел и согласует
альтернативу или отдельную задачу для HoH. Даже если задача описана подробно, он сначала подводит
итог и просит подтвердить план в чате. После подтверждения он создаёт или правит
плагин и запускает проверки. Если задача существенно изменилась, харнесс
сначала уточняет новое решение.

HoH передаёт эти инструкции автоматически в первом сообщении мастера.
Название команды навыка и пользовательская
установка навыка для этого не нужны. Подтверждение плана в чате и системные
подтверждения инструментов действуют независимо.
