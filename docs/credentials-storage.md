# Где HoH хранит ключ модели — решение, 20.11

**Факты по коду.**
- `crates/hoh-credentials-local` — перенос `dsh-credentials-local`. Он хранит ключи только в файле `<данные движка>/.credentials.yaml`: права 0600, каталог 0700, запись `set/unset`.
- Связки ключей (Secret Service, keyring) в движке нет. Crate `keyring` отсутствует в `Cargo.lock` и в `docs/porting/DEPS.md`.
- Так же было и в принятом окне `93a6f994`.
- На рабочем столе основателя будет то же самое: файл, а не запасной путь.
- От инструментов модели файл защищает credguard (`hoh-credentials-guard`).

**Решение (CEO 20.11 18:17, ведущий).**
- Окно прямо говорит человеку, где лежит ключ: «Ключ хранится в файле на этом компьютере: <путь>. Читать его может только ваша учётная запись.»
- Текст ключа окно не показывает.

**Позже — вопрос к основателю, а не к реализации.** Хранение в системной связке ключей требует нового crate через supply-gate (ориентир `keyring` 4.2.0 из `research/desktop-ui-rust.md`). Если связка недоступна, файл остаётся запасным путём, и окно тогда называет его как запасной.
