# HOH-18: Claude и Codex как исполнители в HoH — записка, 20.11

Исследование проведено только чтением (Codex read-only, 20.11 15:21). Бриф: `plans/briefs/research-hoh18-t3.md`. Полный ответ (270 строк): `/mnt/toshiba/alexandrie/hoh/research-out/hoh18-t3.md`. Источник: T3 Code, MIT, коммит 803f21f6. Код пишется только после ответа CEO.

## Как это делает T3
- **Codex.** Долгоживущий `codex app-server -c thread_unload_delay_secs=0` с JSON-RPC по stdio. Порядок: `initialize` → `thread/start|resume` → `turn/start` (cwd, model, approval, sandbox). Текст и шаги приходят уведомлениями `item/*`. «Стоп» — `turn/interrupt`. Разрешения на команды, правку файлов и вопросы входят в сам протокол. Вход проверяется через `account/read`, список моделей — через `model/list`; токены T3 не читает (`CodexAdapterV2.ts`, `CodexProvider.ts`).
- **Claude.** `@anthropic-ai/claude-agent-sdk`, то есть `claude -p --input-format stream-json --output-format stream-json`. Текст приходит как `text_delta`, шаги — как `tool_use/tool_result`, разрешения — через обратный вызов `canUseTool`, «Стоп» — через `interrupt` (`ClaudeAdapterV2.ts`). ACP не используется.
- **История.** Свою проекцию T3 хранит в SQLite. Нативный ID сессии нужен только для продолжения работы в самом CLI.

## Что брать и куда
- Общий Rust-контракт `ExternalHarness` (discover / start_or_resume / prompt / interrupt / events). Это отдельный исполнитель сессии рядом с `hoh-agent`, а не ещё один `hoh-llm-*`: у Claude и Codex свой цикл агента, свои инструменты и своё продолжение. В `hoh-agent` нужен шов для подмены исполнителя (`runtime_types.rs:219-255`).
- Порядок: контракт → Codex app-server → Claude stream/control → позже исходящий ACP для прочих агентов. Вывод «ACP первым» (`research/harness-adapters.md`) верен для сторонних агентов, но не для Claude и Codex: через ACP теряются resume, разрешения и откат.
- **Этап 4 (`hoh-acp`, `acp-app`) не нужен.** В dsh это входящий ACP-сервер, а нам нужен исходящий клиент.
- Сопоставление событий: дельты текста → `session.assistant-stream`; итог → durable `session.event`; команда или файл → `tool/call` + `tool/result`; разрешение → наш `approval/request`; вопрос → `user-question/ask`. Нынешняя проекция окна шаги уже показывает (`projection.mjs:128-338`), новый экран шагов не нужен.
- Claude: Rust сам запускает установленный у пользователя CLI `claude` (`-p --input-format stream-json --output-format stream-json`) и ведёт протокол управления (interrupt, разрешения). Agent SDK в поставку не входит. Оговорка: этот протокол управления Anthropic публично не закрепляет (T3 ходит через SDK). Его устойчивость между версиями CLI — не проверено, нужен тест версии при запуске.
- Переносится только логика и схемы, на Rust. TS-sidecar (Node + Agent SDK + Effect) противоречит направлению порта.

## Безопасность
- Наш `hoh-window-destructive-guard` перехватывает только внутренний `ToolsPreExecute` (`lib.rs:47-136`). Команды Claude и Codex через него не проходят. Нужно вынести классификатор в общий сервис и вызывать его до ответа на нативный запрос разрешения.
- Режимы по умолчанию:
  - Codex — `workspace-write`/`read-only`, сеть закрыта, approval `on-request`;
  - Claude — `default` + `canUseTool`.
  `bypassPermissions`, `danger-full-access` и `never` — только после явного разрешения в окне HoH. Callback Claude не заменяет песочницу ОС. Запуск Claude внутри нашей песочницы не проверен.
- Токены: окно получает только признаки «установлен», «вход выполнен» и список моделей. `auth.json` и ключи не читаются и не копируются.
- MIT: при переносе существенного кода — полный текст MIT и copyright T3 в `NOTICE`. Новых crates не нужно (tokio, serde_json, futures-util, tokio-util уже есть). Условия Anthropic Agent SDK к поставке HoH — не проверено.
