**Рекомендация: (б).** Причины: (1) копируем готовый код T3, основатель одобрил копирование; (2) по прежнему отчёту (`research/desktop-ui-rust.md`, §5) агенты лучше всего пишут разметку и CSS, а с Leptos путают версии — оценка косвенная; (3) pdf.js и uPlot есть только как JavaScript, в (а) мы всё равно связали бы их через склейку; (4) (а) не даёт чистой цепочки: 172 crates со сборочным кодом против 109 пакетов без скриптов; (5) типы протокола в (а) общие с движком, но для (б) их порождает скрипт из JSON Schema (`schemars` уже в `DEPS.md`), что дешевле, чем перенос всего интерфейса. Риск (б), не проверенный: Tailwind 4 требует современного CSS (`oklch`, `color-mix`, слои); подойдёт ли WebKitGTK на целевой машине — выясняет пакет 1, до того как писать экраны. Запасной путь при провале: Chromium вместо WebKitGTK (оболочка Electron, как у T3) — менять оболочку не предлагаю без пробы.

## 2. Экраны

Общее: слева список сотрудников и три раздела, сверху полоска «Данные только на этом компьютере» (раздел 5), справа выезжающая панель просмотра. Слова: сотрудник, задача, кнопка, результат. Слов «плагин», «навык», «агент», «сессия» нет.

**1. Первый запуск** (три шага, можно вернуться).
```
[1 Модель]   Ищу модель на этом компьютере… ✓ Отвечает за 2 с   [Другой адрес…]
[2 Правила]  Интернет: (•) спрашивать про каждый новый сайт ( ) читать открытые сайты сам
             Папка для работы: Документы/HoH  [Выбрать]   Опасное: подтверждаю в отдельном окне
[3 Знакомство] «Я ваш Помощник.»  [Следить за ценой] [Прочитать документ] [Новая задача]
```
Кнопки шага 3 запускают готовые шаблоны (описаны как обычные задачи).

**2. Чат** (единственный, у каждого сотрудника свой).
```
┌ Помощник ▾ ──────────────── 🔒 данные на этом компьютере ┐
│ лента (виртуальная); «Ищу на 3 сайтах…» одной строкой     │
│ карточка результата [Открыть] ; карточка вопроса: «Какая…?» (быстрые ответы) │
├ мои кнопки: [Цена GPU] [Разобрать тендер] [＋]            ┤
│ [ поле ввода, / — свои команды ]            [Отправить/Стоп]│
```
Кнопка запускает задачу или готовую фразу сотруднику. «Стоп» вызывает `session/cancel`.

**3. Сотрудники.** Список карточек (имя, роль в одну строку, статус «работает / ждёт / спит», ближайший запуск) и «Создать». Мастер из четырёх шагов, он же вкладки при правке:
```
Имя и роль:  [Психоаналитик]  «Объясняет, как говорить с человеком»  (шаблоны: Аналитик, Секретарь, …)
Правила:     • Отвечай коротко  • Не обсуждай здоровье   [＋ правило]   (простыми фразами)
Что умеет:   ☑ Психоанализ по Telegram   ☐ Цена GPU   [＋ новая задача]
Разрешения:  интернет: только t.me и выбранные сайты · папки: Документы/Психология · …
Память:      список записей «что он помнит», каждую можно поправить или убрать
Расписание:  см. экран 6
```
**4. Задачи.** Карточки задач с кнопкой «Запустить» и версией; «Новая задача» открывает ленту из четырёх шагов: Описание → Вопросы → Пример → «Да, сохранить» или «Исправить». Рядом «Что я знаю об этой задаче» (правила, источники, образец результата; правка словами) и «Вернуть прошлую версию».

**5. Результаты.** Слева список (по дате, по сотруднику, по задаче), справа просмотр: страница, картинка, график, PDF, таблица; «Сохранить как…». Снизу: «Откуда это взялось» — шаги задачи простыми словами.

**6. Расписание.** Список правил: что, кто, когда («каждый будний день в 9:00», «раз в 2 часа»), последний запуск и итог, «Запустить сейчас», «Пауза». Создание: выбрать задачу и сотрудника, фраза о времени с подсказкой, ввод даты руками. Пропущенные запуски: показываем «пропущен, компьютер был выключен» (движок доставляет только последний пропущенный: `tool-schedule`).

**7. Подтверждения.** Список ожидающих и принятых решений. Само решение принимается не здесь, а в отдельном окне (раздел 4).

**8. Настройки.** Модель (адрес, имя, «Проверить»), Защита (раздел 5), Кнопки (список, правка), Вид (светлая, тёмная, размер шрифта), «Дополнительно» (версия, журнал для поддержки).

**Чего обычный человек не видит никогда:** git, терминалов, различий файлов, рабочих копий, вызовов инструментов в виде JSON, путей вне его папки, названий моделей вне «Дополнительно», слов «токен» и «сессия». Всё это движок хранит, окно не показывает. Настройка «Show coding view» из dsh в нашей сборке отсутствует, а не выключена.

## 3. Пример основателя шаг за шагом

Сначала задача, потом сотрудник, потом запуск. Слово «да» говорит пользователь в местах, отмеченных ◆.

1. Задачи → «Новая задача». Пишет: «Разбирать публичный Telegram-аккаунт человека и советовать, как с ним говорить: нужен точный план или идея». Окно: `task/draft/start`. Движок создаёт черновик и запускает отдельного «строителя» с набором инструментов (интернет, чтение и запись в папке задачи, вопросы, песочница).
2. Строитель спрашивает через `user-question/ask`: что на выходе (портрет общения, три фразы для начала, чего избегать); как задавать аккаунт (ссылка t.me); брать ли фото; какие школы психоанализа. Окно показывает по одной карточке с быстрыми ответами и полем «свои слова».
3. Исследование. Строитель ищет открытые тексты по психоанализу. Окно показывает строки «Читаю 4 сайта…». Новый сайт: если выбран режим «спрашивать», ◆ появляется окно подтверждения «Открыть сайт X?» (раздел 4).
4. Строитель пишет заметки по книгам в папку задачи, затем делает разбор аккаунта: читает публичную страницу t.me, био и тексты, скачивает фото. Для разбора пишет небольшую программу и запускает её в песочнице (без сети, кроме разрешённых адресов).
5. Пример. Строитель выполняет задачу на первом реальном аккаунте, который пользователь указал на шаге 2, и показывает «Пример»: что взяли на входе, что получилось (карточка результата с просмотром справа). Событие `task.example`.
6. ◆ Пользователь нажимает «Да, так» или пишет поправку («короче, без диагнозов»). После поправки движок переделывает и снова показывает пример. Это главное «да» первой версии.
7. Окно предлагает список прав задачи простыми словами: «читает t.me; скачивает фото в папку задачи; запускает свою программу в защищённой коробке». ◆ Подтверждение в отдельном окне. После него движок проверяет структуру, повторяет одобренный пример и сохраняет задачу как активную версию 1.
8. Окно: «Задача готова. Добавить кнопку в чат?» ◆ «Да» создаёт кнопку «Разобрать аккаунт» (запись `button/create`), подпись можно поправить.
9. Сотрудники → «Создать». Имя «Психоаналитик», роль «Объясняет, как говорить с человеком по его аккаунту», правила: «отвечай коротко, не ставь диагнозов». Что умеет: ставит галочку у новой задачи. Разрешения: интернет только t.me. `employee/create`.
10. Расписание (необязательно): «Каждый понедельник проверять аккаунт X и сообщать, если стиль изменился». `schedule/create` с сотрудником и задачей.
11. Запуск: в чате «Психоаналитика» нажимает «Разобрать аккаунт», вставляет ссылку. Движок запускает активную версию задачи на новом входе (без вопросов; сомнение → вопрос карточкой). Новый сайт вне разрешённых: подтверждение.
12. Результат появляется в панели справа: страница «Как говорить с этим человеком» (текст, три фразы для начала, галерея фото). Пользователь спрашивает в чате «а если он обидится?», сотрудник отвечает, опираясь на результат и память.
13. Результаты хранятся на экране 5; повтор по расписанию кладёт новые.

Требование «агент сам собирает книги»: источники — открытые тексты и файлы, которые пользователь перетащит в окно. Скачивание из пиратских библиотек я не предлагаю (вопрос 3).

## 4. Протокол окно ↔ движок

**База.** Остаётся SDK dsh (`packages/sdk/protocol/src/types.ts`): JSON-RPC 2.0 по строкам через stdio, `initialize`, `session/prompt`, `session/query`, `session/resume`, `session/wait`, `shutdown`, уведомления `session.event`, `session.status`, `session.query.completed`, `subagent.*`, обратные запросы `user-question/ask` и `approval/request`. Окно не говорит с движком напрямую: ядро Tauri (Rust) запускает движок как дочерний процесс, держит его stdio, пересылает в окно только разрешённые уведомления и принимает из окна только разрешённые методы. Версия: в `initialize` добавляем необязательные `hoh: {protocolVersion}` и `capabilities.approvals: "host"`; имя сервера остаётся прежним (`deepseek-harness-sdk-runtime`), старые клиенты не ломаются. Протокол не привязан к stdio: кадры одинаковы для любого канала, stdio дочернего процесса — только первый транспорт; позже ядро Tauri подключится к движку на сервере (Spark) по защищённому каналу без изменений в окне (решение CEO 2026-11-18).

**Чего не хватает в SDK и что добавляем.** Новые методы с префиксом `hoh/`, кроме трёх `session/*`. Каждый метод регистрирует свой crate через общую таблицу в `hoh-sdk-jsonrpc-server`.

| `hoh/artifact/render` | `{id, as:"pages"|"table"|"text", page?}` → страницы PNG, строки таблицы или текст | новый `hoh-tools-docs` (docx/pptx через системный `soffice`) |
| `hoh/model/probe` | `{baseUrl, model}` → `{ok, latencyMs, toolCalls:bool}` | `hoh-llm` |
| `hoh/settings/get|set` | настройки без секретов | `hoh-settings`, `hoh-credentials` |
| `hoh/security/summary` | `{}` → `{model:{local:bool,host}, egress:[{domain,count,lastAt}], permissions:[…], approvals:[…]}` | `hoh-sandbox-policy`, `hoh-web`, `hoh-user-approval` |

**Новые уведомления:** `employee.changed`, `task.changed`, `task.draft.state` (`asking|researching|building|example_ready|checking|saved|failed`), `task.example` (вход, ссылка на результат), `schedule.fired`, `schedule.changed`, `artifact.presented` (из события `deliverables/presented`: путь заменяется на `artifactId`, окно путей не получает), `approval.pending`, `approval.resolved`, `security.egress` (домен, сотрудник, размер).

**Путь подтверждения опасного действия** (интерфейсный код один подтвердить не может):

1. Ядро Tauri при запуске порождает случайный ключ 256 бит и передаёт движку через `initialize` по stdio. В окно (JavaScript) ключ не попадает никогда.
2. Движок присылает обратный запрос `approval/request` с `approvalId`, классом риска, `humanText` (текст на языке пользователя, собранный движком из структуры: сайт, папка, права задачи) и `actionHash` — хешем канонической записи действия. Поле `reason`, написанное моделью, показывается отдельной строкой с подписью «Объяснение сотрудника».
3. Ядро не пересылает этот запрос окну как вопрос. Оно открывает отдельное окно Tauri с меткой `approval` и своей страницей из набора файлов, без общего состояния с главным окном. Права (capabilities) этой метки включают одну команду `approval_decide`; в правах главного окна её нет, и главное окно получает только уведомление `approval.pending` для баннера «ждёт решения в отдельном окне».
4. Нажатие в окне подтверждения порождает ответ `{approvalId, outcome, mac}`, где `mac` — HMAC-SHA256(ключ, каноническая запись `{approvalId, outcome, actionHash, risk, humanText, expiresAt}`): подменить показанный пользователю текст или класс риска, сохранив `mac`, нельзя. `actionHash` ядро умеет пересчитать из записи действия. Ядро отправляет его движку. Закрытие окна равно `rejected`.
5. Движок проверяет `mac` и срок (по умолчанию 5 минут, потом `cancelled`). Решение действует один раз, как `allowed-once` в SDK.
6. Фильтр методов в ядре: из главного окна не проходят `approval/*` и `hoh/settings/set` для полей безопасности. Любой метод, который выдаёт или расширяет права (`permissions` в `hoh/employee/create|update`, `hoh/task/draft/decide` с согласием, `hoh/task/rollback` к версии с другими правами, `session/working-directory/set`, `hoh/settings/set` для адреса модели и полей безопасности, `hoh/model/probe` с произвольным адресом), движок выполняет только после `approval/request` с `mac`; перечень таких методов — `PRIVILEGED_METHODS` в `hoh-protocol`, по нему же фильтрует ядро. Повторный `initialize` отвергается: ключ задаётся один раз. `InitializeResult` подтверждает `hoh.approvals: "host"`; ядро, не получив подтверждения, не запускает задачи (иначе движок молча работал бы в старом режиме подтверждений). Захваченный интерфейс может попросить действие, но подтвердить его не может: ни кнопки, ни ключа у него нет.

Остаточные риски: ложная страница в отдельном окне невозможна из окна, но пользователь может нажать «Разрешить» не читая; захваченная ОС. Запрет на нажатие без чтения (задержка кнопки 1 с, крупный текст риска) входит в пакет 4. Не проверено: изоляция webview разных меток в Tauri 2.12 (по `research/supply-chain-ts.md` права привязаны к метке окна), доставка `register_uri_scheme_protocol`.

## 5. Безопасность, которую видит пользователь

Всё говорится словами, не терминами. Источник каждого пункта — `hoh/security/summary` и журнал движка.

- **Полоска сверху:** «Данные только на этом компьютере» (модель локальная) или «Запросы уходят в X» (внешняя). Нажатие открывает страницу «Куда уходят данные»: сайты, куда ходили сотрудники сегодня и за неделю, по каждому число запросов, кто ходил.
- **Права сотрудника** в его карточке: «Читает интернет: только t.me и 2 сайта», «Видит папки: Документы/Психология», «Меняет файлы: нет», «Запускает программы: только в защищённой коробке, без интернета», «Пишет за вас: нет». Рядом переключатель каждого права и слова «Что будет, если включить».
- **Права задачи** показываются перед сохранением (шаг 7 примера) и в карточке задачи; после правки они пересчитываются, и новое право просит подтверждения заново.
- **Подтверждения:** история решений, кто просил, что именно, когда и ваш ответ; отдельное окно, которое не может нажать само окно с чатом.
- **«Защита этой копии»:** версия, подпись приложения проверена, обновления принимаются только с нашей подписью, окно не может читать ваши файлы и запускать программы — только просить об этом движок (по `research/supply-chain-ts.md`, слой 5; настройка CSP и прав обязательна, `connect-src` без внешних адресов). Честно написано, чего это не закрывает (ошибка проверяющего, дыра в системном окне).
- Личные данные других людей (пример основателя: био и фото из чужого аккаунта) хранятся только в папке задачи на этом компьютере; на странице «Что я знаю» это видно. Юридическую сторону разбора чужих аккаунтов я не проверял.

## 7. Решения по вопросам (CEO, 2026-11-18)

1. Программа, написанная моделью, внутри задачи: да (ответы основателя 2 и 7). Песочница, сеть только по разрешённым адресам, права показываются и подтверждаются при сохранении задачи. Запрет в `PLAN.md` снят.
2. Движок в первой версии на том же компьютере, дочерним процессом окна. Протокол не привязывать к локальному запуску (раздел 4): сервер на Spark подключится позже без переделки окна.
3. Книги: открытые тексты из сети и файлы, которые пользователь положил в окно. Пиратские библиотеки не используются; агент ищет сам, но берёт только открыто доступное.
4. Word и PowerPoint показываются через LibreOffice, если он установлен (`/usr/bin/soffice` на этой машине есть); иначе окно предлагает открыть файл во внешней программе. В состав продукта LibreOffice в первой версии не входит. `xlsx` — таблицей без него.
5. Слова «сотрудник», «задача», «кнопка», «результат»; только русский язык в первой версии.
