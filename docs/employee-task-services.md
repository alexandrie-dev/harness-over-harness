# Сервисы hoh-employee и hoh-task за готовым протоколом — 20.11

Исследование только чтением (Codex read-only, бриф `plans/briefs/research-employee-task.md`, полный ответ `/mnt/toshiba/alexandrie/hoh/research-out/employee-task.md`). Протокол `hoh/employee|task|button|schedule|memory` уже полный (`crates/hoh-protocol/src/hoh.rs:33-266`), но исполняет его только заглушка (`crates/hoh-window-stub/src/engine.rs:340-350`).

**Из чего собирается (всё принято):** роль — `hoh-persona` (persona на агента/сессию); сотрудник как композиция — `hoh-agent-preset` + `-registry` (каталог, фиксация в журнале сессии); правила рабочей папки — `hoh-agent-instructions` (правила сотрудника материализует новый сервис); хранение — `hoh-storage-domain` (KV-домены с версиями) + `hoh-storage-json`; сессии — `hoh-session` + `-persistence-jsonl`; поиск по истории — `hoh-session-query[-sqlite]` (не память); расписание — `hoh-schedule` (after/at/every/daily/weekly/cron/RRULE, доставка в сессию); вопросы — `hoh-user-questions` (по сессии); RPC — реестр методов в `hoh-sdk-jsonrpc-server`; поручение-скилл — `hoh-skill`/`hoh-tool-skill`, строитель — `hoh-subagent*`.

**Чего нет (новый код):**
- `hoh-employee`: запись сотрудника с ревизией и статусом, связь сотрудник↔пресет↔сессии, правила, заметки памяти, удаление; пауза (в протоколе нет `paused`).
- Материализация сотрудника в persona/preset/instructions, инструменты и права при каждой сессии.
- `hoh-task`: «описание → вопросы → пример → поправка/«да» → проверка → неизменяемая версия», повтор принятых примеров, откат.
- Кнопки (протокол есть, исполнителя нет); адаптер расписания на сотрудника+поручение (сейчас цель — сессия); защита от повторного запуска после сбоя.
- Общий список вопросов всех сотрудников для главной (сейчас вопрос привязан к сессии).
- Подключение этих крейтов в `apps/hoh` (сейчас в реестре нет preset/instructions/schedule).
