## Вопросы

### 1. Что тебе нравится в T3 Code

Отметь важное, добавь своё.

1. Много тредов и проектов в одном окне, всё видно сразу.
2. Исполнители в фоне: дал задачу, занимаешься другим, тебя будят по готовности.
3. Разные модели и харнессы под одной крышей (Claude, Codex и другие).
4. Делегирование: один агент раздаёт работу другим.
5. Предпросмотр результата прямо в окне (страницы, картинки, графики).
6. Расписание и задачи по таймеру.
7. Сам вид и скорость интерфейса.

Ответ: В первой версии не нужно много харнессов, мне важно чтобы этот продукт был прост в освоении. Важное: 5 6 7. И еще удобный интерсфейс для создания виртуальных сотрудников в компании. В теории мы можем для интерфейса использовать TypeScript, нужно будет только как-то придумать схему где мы защищены от supply-chain атаки, безопасность мы будет показывать как тоже достаточно большую фичу.

### 4. Что делаем первым: оболочку или свой движок

- (а) Оболочку как у T3 Code поверх готовых движков (Claude Code, Codex, Qwen Code через ACP).
  Пользоваться можно через недели. Свой движок на Rust дописывается параллельно и подключается
  как ещё один.
- (б) Сначала свой движок до прохождения сценариев dsh, потом окно. Это нынешний план;
  до первого окна далеко.
- (в) Только оболочку, перенос движка остановить.

Моя рекомендация: (а). Причина: то, что тебе нравится в T3 Code, живёт в оболочке, а не в движке.
Сделанное по переносу не пропадает: ядро плагинов, загрузчик и слой модели нужны и оболочке.

Ответ: Б. Если добавление TypeScript в проект ускорит разработку, давай добавлять. Мы же можем по факту просто копипастить.
