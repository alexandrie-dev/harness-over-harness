# Рабочие деревья писателей и конфликты — 20.11, 19:3x

Указание основателя через CEO: «разреши там все конфликты и сделай так, чтобы они не мешали друг другу».

## Как устроено (чем обеспечена гарантия)

- **Своё дерево у каждой цепочки.** Каталог `/mnt/toshiba/alexandrie/hoh/wt/<писатель>`, ветка `w/<писатель>`.
  - Создаётся в начале первого хода после перехода (`scripts/claude-writer.sh`) из снимка общего дерева в этот момент. Несданная работа писателя переезжает вместе с ним, без ручного разбора по файлам.
  - Писатели git не меняют, поэтому ветка = база, правки = рабочие файлы дерева.
  - Свой каталог сборки у писателя был и раньше: `target-<писатель>`.
- **Пакет = явный список путей.** Это `crates/<крейт>`, для `hoh` — `apps/hoh`. Коммит пакета C собирает `scripts/pkg.sh commit`:
  - трёхстороннее слияние путей пакета: база ветки писателя → правки писателя → нынешний main (`git merge-tree --merge-base`);
  - чужие правки в том же крейте, уже попавшие в main, не затираются;
  - конфликт в коде пакета останавливает пакет. Вариант писателя сохраняется в `refs/hoh/conflict/<id>/writer`, задание уходит к ведущему.
- **Общие файлы в пакет не входят никогда.** Это `Cargo.toml`, `Cargo.lock`, `docs/porting/MAP.tsv`, а в `apps/hoh` — `Cargo.toml`, `src/lib.rs`, `src/registry.rs`, `src/v1_registry.rs`, `src/profile_boot.rs`, `tests/built_bin.rs`. Их вносит интеграция.
- **Прогон, ревью, приёмка, коммит идут по одному C.**
  - Прогон: дорожки `it/run-a`, `it/run-b`.
  - Ревью: выгрузка `it/rev-<id>` и дифф `pipeline/reviews/<id>.diff`.
  - Приёмка: `it/acc-a`, `it/acc-b`.
  - Коммит: `commit-check --pkg C`.
- **`commit-check` не трогает индекс общего дерева.**
  - Кандидат собирается во временном индексе от HEAD: пути пакета из C, MAP — из интеграции.
  - Проверка «изменённое ⊆ пути пакета ∪ Cargo.lock», иначе отказ.
  - Затем чистая выгрузка, `cargo check --locked`, `update-ref` с проверкой, что HEAD не сдвинулся.
- **Зависимости.** `pipeline/deps.tsv`: tool-jobs ← jobs-local, harness-claude ← external-harness.
  - Сосед подкладывается в C из дерева своего владельца (`pipeline/owners.tsv`).
  - Коммитится только свой путь: пакет ждёт в очереди коммитов, пока сосед не в main, затем проходит сам.
- **Сценарии на main.** `scripts/conformance-main.sh`: выгрузка HEAD, 2 задания. Писатели гоняют свои сценарии точечно в своих деревьях.
- **Общее дерево — только интеграция.** `scripts/main-cleanup.sh`:
  - ждёт, пока в нём не останется ходов;
  - коммитит файлы интеграции;
  - снимает общее дерево (ref и архив);
  - создаёт недостающие деревья (в том числе `parked`);
  - возвращает дерево к HEAD. `design/` не трогается.
- **Страховка.** Снимок всего грязного дерева до перехода: `refs/hoh/snapshot-20261120-1924`, архив `/mnt/toshiba/alexandrie/hoh/snapshots/dirty-20261120-1924.tar.gz` (1143 файла относительно HEAD).
