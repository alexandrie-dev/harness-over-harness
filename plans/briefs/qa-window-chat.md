# QA вехи «окно-чат»: проход как пользователь

Исполнитель: отдельный запуск Codex (QA). Ему разрешено собрать и запустить приложение headless (xvfb)
на отдельных данных. Код не правит. Находки сообщает отчётом, исправляет их писатель.

## Что проверяется

Условие вехи (CEO 18.11 23:57): запуск приложения; окно по `docs/window.md`; первый запуск с вводом адреса
и API-ключа (OpenAI-протокол, ключ хранится через `hoh-credentials`); потоковый ответ модели; bash и файлы;
шаги в ленте; подтверждение опасного в отдельном окне.

Проверяемая сборка — коммит, который назовёт ведущий в запуске (`git rev-parse HEAD` записать в отчёт).
Собирать из чистой выгрузки этого коммита (`git worktree add <слот> <коммит>`), а не из рабочего дерева.

## Окружение (обязательно)

- Только headless: `ui/scripts/run-isolated-window.py <бинарь> …`. Он даёт временный HOME/XDG, xvfb и
  свою шину. Другие дисплеи, браузер с экраном и реальный HOME не использовать.
- Данные: отдельная рабочая папка в `/mnt/toshiba/alexandrie/hoh/qa/<дата-время>/` (Документы/HoH
  пользователя — внутри неё). Никаких путей в настоящем `$HOME`.
- Сборка: `CARGO_TARGET_DIR=/mnt/toshiba/alexandrie/hoh/target-qa`, `--offline`, `CARGO_BUILD_JOBS=2`.
- Модель, прогон A (обязательный): сценарный OpenAI-совместимый mock (`/v1/models`, `/v1/chat/completions`
  с SSE и `tool_calls`; его даст ведущий вместе с запуском — `hoh-llm-mock-server` из dsh отвечает только
  на `/v1/messages` и для окна не подходит) на свободном локальном порту (проверь, что порт свободен;
  порт 8000 занят чужим TLS-прокси — не трогать). Сценарии ответов: потоковый текст, вызов инструмента
  `bash`, вызов `read`/`write`, опасная команда.
- Модель, прогон B (живой): только когда ведущий передаст адрес, имя модели и ключ отдельным файлом.
  Ключ не печатать в отчёт, лог и снимки; в отчёте — только адрес и имя модели.
- Не запускать: сервер модели на GPU, что-либо в очереди GPU, установки пакетов, сетевые обращения кроме
  mock-сервера и (в прогоне B) адреса поставщика. Чужие процессы не останавливать.
- Каждый запуск под `timeout`. Свои процессы по завершении остановить; PID и код выхода — в отчёт.

## Сценарий (каждый шаг: действие → что должно быть видно → доказательство)

1. Запуск приложения из чистой выгрузки. Окно открывается, слева сотрудники и разделы, сверху полоска
   «Данные только на этом компьютере». Снимок.
2. Первый запуск, шаг «Модель»: «Другой адрес…», ввод адреса mock-сервера и ключа, «Проверить» →
   «Отвечает». Ключ не виден в окне после ввода. После перезапуска приложения повторно не спрашивается
   (ключ сохранён через `hoh-credentials`; в каталоге данных — не открытым текстом в конфиге).
3. Шаги «Правила» и «Знакомство» проходятся; «назад» работает.
4. Чат «Помощник»: сообщение → ответ появляется по частям (не одним куском). Доказательство: два снимка во
   время потока или журнал событий окна с несколькими частями. «Стоп» прерывает поток.
5. Файлы: попросить прочитать файл из рабочей папки → в ленте шаг одной строкой («Читаю …»), в ответе
   содержимое. Попросить записать файл → файл появился в рабочей папке с ожидаемым текстом (`cat` в отчёт).
   Путь вне рабочей папки — отказ, понятный человеку.
6. bash: безопасная команда (`ls`, `echo`) → шаг в ленте, результат в ответе. Опасная (`rm` в рабочей
   папке) → отдельное окно подтверждения. «Нет» → команда не выполнена (файл на месте). Повтор, «Да» →
   выполнена. Подтверждение появляется в разделе «Подтверждения». (CEO 19.11 18:00) Окно подтверждения
   говорит по-человечески и по-русски: что будет сделано, с какими файлами, почему опасно («файлы не
   попадут в корзину»); сырая команда только в подробностях. Удаление: «Отклонить» → файлы на месте;
   «Разрешить один раз» → удалены; такой же вызов снова → снова спрашивает. Перезапись существующего
   файла (`>` / `sed -i`) — тоже вопрос. Просьба модели о полном доступе (выход из песочницы) — вопрос
   тоже по-русски. Обратная проверка: не меньше 10 обычных команд (ls, cat, grep, mkdir, запись нового
   файла, `$(date)`, конвейер без оболочки на конце, `python3 скрипт.py`) — ни одного окна подтверждения.
   Сценарий mock для этого шага ведущий даёт в запуске.
7. Лента не показывает JSON вызовов, слова «токен», «сессия», «агент», пути вне папки пользователя
   (`docs/window.md`, раздел 2, последний абзац).
8. Перезапуск приложения: история чата на месте.
9. Прогон B (живая модель): шаги 2, 4, 5, 6 с настоящим поставщиком.

## Отчёт

`/mnt/toshiba/alexandrie/hoh/logs/qa-window-chat.<прогон>.report.md`, по-русски. Первая строка строго:
`QA окно-чат <A|B>: пройдено N из M, блокеров K`. Далее таблица шагов: шаг, результат (да/нет/не проверено),
путь к снимку/логу. Для каждой находки: сценарий, что ожидалось, что видно, доказательство, ссылка на
требование; пометка: блокер (непроходимый путь, потеря данных, опасное без подтверждения), нарушение
требования или вкус. «Не проверено» писать прямо — без доказательства шаг не считается пройденным.
