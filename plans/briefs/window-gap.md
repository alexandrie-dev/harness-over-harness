# Окно: обработка кадра `gap` живого потока ответа (20.11 02:15, решение CEO)

## Что произошло
Коммит bff14047 ограничил очередь уведомлений сервера (`crates/hoh-sdk-jsonrpc-server/src/transport.rs`, PORT_NOTES там же). При перегрузке части `session.assistant-stream` (chunk) попытки сворачиваются в кадр
`{type:"gap", attemptId, revision, index}` (схема: `crates/hoh-protocol/src/sdk.rs` `SessionAssistantStreamFrame::Gap`, `protocol/core.ts`, `ui/src/protocol.ts`). После `gap` в этой попытке живых chunk больше не будет; `end` придёт; итоговое `assistant/message` (durable `session.event`) остаётся каноном и заменяет живой текст (`settleLive`).
Сейчас `ui/src/screens/chat/projection.mjs` `liveFrame` кадр `gap` игнорирует, а по `end` снимает `streaming` — обрезанный префикс выглядит как готовый ответ.

## Что сделать (границы CEO)
Только обработка `gap` в проекции и то, что для неё строго необходимо (например контроллер `ui/src/screens/chat/controller.mjs`, если нужно подтянуть итог). **Разметку, компоненты `.tsx` и стили не менять.**
Поведение:
1. После `gap` окно показывает уже полученный текст, но НЕ считает его окончательным: `end` этой попытки не снимает признак «ещё пишется» (`streaming`), пока не придёт итоговое `assistant/message` (settleLive заменит текст целиком).
2. Если итог не приходит обычным путём (ход закончился — `turn/end`, отмена, ошибка, переподключение/перезагрузка истории) — не оставлять навсегда вечный курсор и не выдавать префикс за полный ответ. Посмотри, позволяет ли протокол подтянуть итог (история сессии/`session/read`/перезагрузка страницы истории, как делает контроллер после reconnect) — если да, подтяни; если нет — по `turn/end` сними `streaming`, а запись оставь такой, чтобы окно не считало её финальным ответом (опиши, как именно, без новых стилей).
3. Кадры после `gap` той же попытки (chunk с большим index) игнорируются; `gap` чужой/retired попытки игнорируется; revision правила прежние.
4. Ничего другого в окне не менять.

## Тесты
- В наборе окна (`ui/tests/chat/projection.test.mjs` и/или `controller.test.mjs`, запуск через `ui/tests/chat/run.mjs`): start → chunks → gap → (chunk после gap отброшен) → end: запись остаётся streaming с префиксом; затем assistant/message → полный текст, streaming false. И случай без итога: gap → end → turn/end — поведение п.2. Тест должен падать на нынешнем коде.
- Прогон на настоящем движке с mock при искусственной перегрузке: оцени, достижим ли он без переделки mock (`crates/hoh-llm-openai-mock`) — mock менять нельзя. Перегрузка очереди требует медленного читателя stdout движка; посмотри, как окно/натив (`apps/hoh-desktop`) читает движок и есть ли тестовый путь. Если достижимо малыми средствами — сделай (например тест, который запускает настоящий `hoh` с mock, не читает stdout до накопления, затем читает и кормит кадры в проекцию). Если нет — напиши, чем заменил (например записью реальной последовательности кадров из `crates/hoh-sdk-jsonrpc-server/tests/transport_bounded.rs` в фикстуру и прогоном проекции на ней) и почему.
