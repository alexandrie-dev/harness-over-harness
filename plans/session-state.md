# Harness Over Harness — состояние

Обновлено: 2026-11-16. Ведущий: основная сессия Claude Code.

## Бриф основателя (2026-11-16, диктовка; расшифровка ведущего, спорные места помечены)

- Новый большой продукт группы Alexandrie. Рабочее имя папки `HarnessOverHarness`; в конце диктовки
  прозвучало «Alexandrie Harness» — какое имя продуктовое, **не подтверждено**.
- Харнесс стоит над другими харнессами: внутри него запускаются Claude Code, Codex и другие.
  За основу «возьмём код T3» (T3 Code, pingdotgg/t3code); ссылку основатель пришлёт.
- Пишем всё на Rust. Мультиплатформенность: Linux, macOS, Windows.
- Философия DeepSeek Harness «everything is a plugin» перенимается; своя добавка: «every task is a plugin».
  Основатель упомянул статью с алгеброй (в диктовке «кетологическая», вероятно «категорная») и предложил
  разобрать её вместе в Excalidraw.
- Идея отличается от самопереписывающихся харнессов (упомянуты Ouroboros и «Harness квадрат» —
  второе **не опознано**, кандидаты Self-Harness arXiv 2606.09498 и Meta-Harness).
- Зачем: заказчику нужен локальный ИИ, у него DGX Spark, запускаем Qwen. Он назвал одну задачу
  (работа с документами, распарсить сайт). Новые задачи появятся, и мы не хотим каждый раз приходить
  и дописывать харнесс руками. Пользователь пишет «мне нужно решать такую-то задачу» — харнесс
  перестраивается под неё (ищет источники, пишет тулзы и прочее), дальше задача решается быстро,
  «по накатанным рельсам». По сути это продвинутая memory.md с тулзами.
- Нужно задизайнить бенчмарк харнесса.
- Рынок условно российский: пользователи слабо владеют ИИ, знания базовые. Главное качество —
  минимальный порог входа; «простой» не значит «слабее Claude Code».
- Ресурсы и время не ограничены: субагенты, исследования, работа днями. Codex желателен как ревьюер.
- Основатель просил допросить его конкретными вопросами.

## Решения основателя

Ответ 1 (2026-11-16, диктовка):

- Пользователи у заказчика: несколько сотрудников без навыков программирования, не айтишники; задачи
  довольно простые. Мой вариант «каждый со своего ПК по сети, Spark общим сервером» принят словами «всё так».
- Короткое имя: **HoH** («Хох»); полное прозвучало как «Alexandrie Harness Over Harness».
- У HoH есть **свой харнесс по умолчанию**: DeepSeek Harness, переписанный на Rust «по образу и подобию»,
  дальше улучшаем. Это первая очередь.
- Claude Code, Codex и прочие можно будет запускать внутри HoH со всеми их возможностями, но эта
  поддержка **позже**; сейчас главное — лёгкий в подстройке харнесс.
- Большая цель: унифицировать и «поглотить» узкие ИИ-стартапы (пример: ИИ-бухгалтер). Сценарий основателя:
  клиенту харнесс понравился, он просит больше автономии (скрытый запрос на автономного ИИ-бухгалтера);
  в HoH он нажимает одну кнопку, описывает модели, что хочет видеть, и получает готовый результат.

- Первоисточники: `deepseek-ai/deepseek-harness` (MIT, TypeScript, Node ≥ 24.9, developer preview, версия

- Статья формализует не теорию категорий, а две вещи: откатываемые эффекты (моноид пар «действие, обратное»,

  dsh (образец 83 тыс. строк TypeScript): ядро и loader, позвоночник агента, модель с одним адаптером
  Chat Completions, журнал сессий, файлы и оболочка, разрешения и sandbox, сжатие контекста, skills/todo/plan,
  субагенты и MCP, внешний протокол уровня SDK.
- Переносить семантику: эффект с обратным действием, владение по fiber, committed view, ожидание зависимых
  при выгрузке провайдера, реактивный `inject`, слои конфигурации, перекомпоновку без перезапуска.
  Не переносить: `Proxy`, замену кода на лету (сами сопровождающие предлагают её убрать), `!!js` в YAML, npm.

- В dsh нет встроенной памяти и нет механизма «задача = плагин»; ближайшее — экспериментальные

Выводы из разбора кода аналогов плагина задачи (раздел 8 отчёта — готовый вход для плана):

- Формат: каталог в стандарте Agent Skills (`SKILL.md`, `scripts/`, `references/`, `assets/`) плюс отдельный
