# Исправления первого запуска и подтверждения

Ревью: `/mnt/toshiba/alexandrie/hoh/logs/rv-screens-a.full.md`. В этом круге браузер в песочнице Codex не запускается; screens-a и chat behavior проверяет ведущий снаружи, с временным HOME и без сети. Сборки pnpm/cargo не запускались, crates и исходники экрана чата не менялись.

1. API-ключ — неконтролируемое поле с ref, без значения в React state. Временная строка читается перед сохранением и сбрасывается в finally при успехе, ошибке или раннем выходе. Успех очищает поле; ошибка оставляет ввод для повтора и показывает общий текст без диагностик с секретом. Node и внешний сценарий проверяют ошибку и повтор.
2. Истечение вычисляется при каждом рендере через Date.now. Уже просроченный запрос сразу показывает итог без кнопок. decide повторно сверяет время до отправки. Есть проверки начальной просрочки и перехода дедлайна между тиками.
3. Ошибка отправки сохраняет ожидающий ApprovalView. Esc/pagehide могут повторить rejected, пока запрос не обработан и срок не вышел. Успех снимает обработчики, повторный ответ не отправляется. Нативное закрытие обеспечивает ядро cf1; тест страницы эту гарантию не подменяет.
4. Fieldset блокирует все поля и кнопки мастера при проверке, сохранении и выборе папки. Синхронный ref не даёт начать вторую операцию до обновления React. Проверяются сохранения модели/правил, ошибка и разблокировка; также два быстрых нажатия «Проверить» во время сохранения ключа.
5. Ручное имя модели находится только в закрытом «Дополнительно». По умолчанию probe получает пустое имя для автообнаружения, затем выбирается первая модель из списка; ручное имя имеет приоритет. В текущем generated protocol поле models ещё отсутствует: чтение из ответа изолировано в modelsFromProbe в engine.ts. Если список отсутствует, используется сохранённое имя; при отсутствии обоих UI предлагает ручной ввод в «Дополнительно». protocol.ts не редактировался.
6. Для явно указанного удаления текст конкретный: «Файлы не попадут в корзину. Восстановить их будет нельзя». Отдельные последствия есть для запуска программы, изменения файла и передачи данных. ApprovalView не содержит структурированного вида действия: классифицируется только явная формулировка humanText, общий текст остаётся для неизвестной формулировки.
7. Общая fixtures.mjs задаёт humanText одной допустимой строкой с файлами через запятую. Переносы строк и выдуманное поле списка не используются. Node проверяет исходную фикстуру, браузерный сценарий использует ту же строку; отображение — React-текст.
8. Во всех трёх CSS литерал 100dvh заменён на var(--viewport-height), значение находится в tokens.css. Проверка литералов распознаёт dvh/svh/lvh/vh/vw и варианты ширины/регистра; подложенные литералы дают отказ.

Результат: screens core **12/0**, существующий chat/core **64/0**; проверка литералов — **0 находок в 11 файлах**. В screens core входит полная проверка TypeScript без emit. Логи — ui/test-results/screens-a/.

Браузерные регрессии находятся в run.mjs; их синтаксис проверен, исполнение и новые снимки остаются ведущему. В chat behavior обновлена только fixture первого запуска: модель выбирается автоматически, скрытое поле не заполняется.
