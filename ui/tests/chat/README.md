# Чат A: поведение и приёмка

Вариант основателя — `design/round1/a`. `ChatScreen` использует только общие `ui/src/styles/tokens.css`: все 19 переменных `--chat-*` перенесены туда без изменения значений, `chat-tokens.css` удалён. Светлая палитра включается атрибутом `data-theme="light"` у корневого элемента; геометрия A общая для обеих тем. В компонентах нет литеральных цветов/размеров. Первый запуск подключён через `FirstRun.onFinish`: пример переносится в поле ввода, работа не начинается без «Отправить». В localStorage остаётся только булев UI-маркер завершения, не ключи, права или настройки модели.

## Что проверяется

Zustand-адаптер использует независимый от React production-контроллер: session/prompt, session.event/status, session/cancel, история страницами по 1000 с exclusive afterSeq, защита от дублирования и поздних ответов после отмены. «Стоп» сначала применяет целиком все уже полученные события, включая сообщение в процессе анимации и очередь за ним, затем закрывает приём поздних событий до новой отправки. Пока cancel не подтверждён, новый prompt закрыт. Подписка на нативный `engine-status` сохраняется при разрыве: окно выходит из ready/busy, показывает «Связь с Помощником прервалась, восстанавливаю…», а после ready заново загружает историю. Подтверждённый ввод сохраняется и из inbox до начала хода; незавершённые шаги старого процесса получают итог «остановлено». При загрузке старой истории текст не анимируется.

Поток text-turn: чанки из data.stream внутри assistant/message — SD → SDK → SDK snapshot → SDK snapshot OK. Reasoning, runtime/system, usage и служебные JSON вызовов не показываются. Свободный текст Помощника, включая технические слова и JSON, не переписывается: в нём скрываются только пути вне рабочей папки. Технические термины и JSON в создаваемых окном деталях заменяются понятным запасным текстом. Готовые строки и Markdown-блоки мемоизированы; LegendList виртуализирует ленту.

Источник шагов — `/mnt/toshiba/alexandrie/hoh/refs/deepseek-harness/snapshots/sdk/persistent-tools/session.v4.jsonl`. Семь шагов: четыре команды, две записи и чтение note.txt. Виден в том числе неуспешный код девять. Раскрытие показывает короткий текст, а не аргументы JSON или пути вне рабочей папки. Stub читает запись и не исполняет её программы/файловые операции.

Markdown: конвейер T3 (react-markdown + remark) → элементы React, сырой HTML остаётся текстом. HTML, картинки и ссылки инертны. Браузер проверяет девять вредных строк, отсутствие исполняемых DOM-элементов/внешних запросов и сохранение текста.

## Fix chat 3 — MIME-тип в data URI

По сообщению ведущего, после fix chat 2 внешний build прошёл (516267/524288 байт текста, 160605/163840 gzip), screens-a **16/0**, behavior — первые пять PASS, затем safe-markdown FAIL: наблюдались 8 из 9 строк. Исполнение разметки не обнаружено. Запас бюджета dist учитывается: новых зависимостей и ресурсов нет, изменение production-кода ограничено распознаванием MIME-заголовка.

Девять исходных строк и их ожидаемый вид вынесены в общий тестовый `markdown-cases.mjs`, который используют Node и behavior. На старом фильтре девять отдельных Node-проверок дали один отказ: пятая строка `![Картинка](data:image/svg+xml,<svg onload=alert(1)>)` превращалась в `![Картинка](data:imageфайл,<svg onload=alert(1)>)`. `/svg+xml` — часть MIME-типа, а не путь. Фильтр сужен: сохраняет MIME-заголовок data URI перед `;` или `,`, но продолжает скрывать внешние пути в содержимом URI и атрибутах. Ожидание пятой строки не ослаблено; единственная ожидаемая замена среди девяти строк по-прежнему относится к `file:///etc/passwd`.

Node/core после исправления: **64/0**, включая каждую из девяти строк, варианты MIME-заголовка, скрытие путей в data URI и прежнюю матрицу обрамлений. Лог воспроизведения: `ui/test-results/chat/core-fix3-before.tap`; итоговый: `ui/test-results/chat/core.tap`. Браузер, сборки и сеть в этом круге не запускались; внешняя браузерная приёмка после fix chat 3 остаётся ведущему.
